## 游戏启动检查

这个开关在「设置 → 游戏运行」中，默认开启。它跟踪打开游戏或重载网页时的三个阶段，依次是应用网络设置、加载入口网页、等待游戏本体就绪。如果入口是登录页，登录表单可操作时就会收起面板。游戏入口则还要等页面或画布可用。应用检查更新、账号认证和数据包版本各有自己的流程。[上游启动实现](../lib/src/game_webview.dart) · [共用的检查界面](../lib/src/browser/game_startup_overlay.dart)

| 用户会看到什么 | 上游实现 | 本次 iOS 处理 |
| --- | --- | --- |
| 当前阶段与进度 | 显示连接、入口和游戏阶段。取得资源活动快照时可显示请求计数 | 接入同一个设置和多语言面板，用 WKWebView 的加载进度、主文档完成和页面可用性检测驱动显示。普通加载面板允许触摸穿透 |
| 长时间没有进展 | 前台 20 秒没有进展时提示可继续等待或重载，另有导航超时 | 使用上游默认的 45 秒前台导航期限，进入后台暂停。开启检查时，连续 20 秒无进展会提示等待或重载。关闭检查只保留简化界面和导航失败恢复 |
| 失败、关闭和重试 | 区分入口错误、特定启动脚本失败及部分本地 HTTP 代理故障，提供操作和详情 | 对可观测的主文档 HTTP、网络和超时错误提供提示。检查面板可关闭、重载，使用应用代理时还可切回系统网络。详情仅显示可用的主机和错误码 |
| 请求数、子资源和代理探测 | Android 原生 WebView 可统计拦截的请求，识别特定 gadget 脚本和本地代理连通性错误 | iOS 当前桥接观测主文档。精确子资源计数、指定脚本归因和 Android 本地代理探针未移植，界面省略这些字段。若以后增加页面侧观测，应单独验证跨域 iframe 覆盖率 |

旧 iOS 提交 `c0715833` 给整次加载加了 15 秒前台上限。此前的 1.10 草案在关闭检查时仍会恢复旧上限。现在仅 build 40 保留 15 秒规则。1.0.9 的通用移植只处理页面就绪、WebKit 真实错误与重试。1.10 的通用移植还要让上游新增的启动检查正常工作，因此接入了分阶段诊断和导航期限。关闭诊断面板后，导航期限仍为 45 秒。

WKWebView 的百分比表示页面加载进度。游戏接口可用性和玩家成功登录需要另行验证。[iOS WebView](../lib/src/ios_game_webview.dart) · [原生导航桥接](../ios/Runner/Bridge/IOSWebViewRuntimeBridge.swift)

## 通知页、精确闹钟与 AlarmKit 预览

旧版已经使用 Android 的「精确闹钟」和「通知渠道」文案。1.10 重排了系统状态及常驻通知选项，把三个状态合并计算。在 iOS 上沿用这个计数会把一个无需申请的 Android 权限算作已通过，也会把系统横幅设置误称为通知渠道。

| 能力 | iOS 的处理 |
| --- | --- |
| 远征、入渠、建造等到点提醒 | 保留类型、提前量和声音设置。已有 Swift 桥接会按任务标识和目标时间提交本地通知，并在快照变化时撤销过期请求。系统负责后台投递，专注模式与系统通知设置会影响呈现。[Apple 本地通知](https://developer.apple.com/documentation/usernotifications/scheduling-a-notification-locally-from-your-app) |
| 权限和排障入口 | 页面读取真实的通知授权状态。首次可申请授权，已有决定后点击进入系统设置。iOS 16 及以上可直达应用通知设置，更早版本进入应用设置。隐藏 Android 精确闹钟、渠道、三项计数和省电说明。[iOS 通知桥接](../ios/Runner/Bridge/IOSNotificationBridge.swift) |
| 锁屏、灵动岛、震动 | 锁屏计时沿用 Live Activities，显示远征、入渠或建造计时。项目按 iPhone 的 iOS 16.1 起、iPad 的 iPadOS 17 起判断支持。普通系统通知的震动显示 iOS 系统说明。Android 常驻通知的进度、百分比和倒数开关由 iOS 的实时活动设置取代。[实时活动桥接](../ios/Runner/Bridge/IOSLiveActivityBridge.swift) |
| 系统闹钟（预览） | 仅 iOS／iPadOS 26 及以上显示，默认关闭。主动开启时申请独立的闹钟授权。若已拒绝，页面提供应用设置入口。预览使用 AlarmKit 的固定时间闹钟，静音或专注模式下也可能响铃。[Apple AlarmKit 调度与授权](https://developer.apple.com/documentation/alarmkit/scheduling-an-alarm-with-alarmkit) |

预览仅替换远征、入渠修理、建造的**完成提醒**。提前提醒、泊地修理、士气和即时消息沿用普通通知。关闭提醒声音时，完成提醒也回到静音的普通通知。闹钟成功注册后撤销同一项普通通知，重复快照复用同一闹钟。时间变更、任务撤销和账号切换按最新快照重新调度。授权被拒绝或单项注册失败时，普通提醒仍依赖系统通知授权。

## 本次拆分验证

- Flutter 3.47.9 对照上游逐个分析改动的 Dart 源文件。通用版 26 个、完整版 32 个，两次均为 0 个问题。
- 1.0.9 与 1.10 的通用移植均已独立编译。最终 1.10 通用版和完整版分别用 Flutter 3.50.0 编译了无签名真机 Release，版本均为 1.10.0（50），最低 iOS 15。通用安装包没有 Widget、AlarmKit 链接及闹钟用途声明。完整安装包包含计时 Widget、WebGL 资源及弱链接的 AlarmKit，也通过了 Flutter 3.47.9 的模拟器 Debug 构建。
- 在同一工作目录切换 Flutter SDK 时遇到 Xcode 预编译头缓存失效。通用版的最终构建使用独立的临时 DerivedData 目录完成。上游锁定的 WKWebView 插件在 Xcode 中仍有 SecTrust 旧接口的弃用警告。
- 在 iPhone 18 Pro 模拟器上实际连续点击设置七次，看到开发者模式开启，并在数据管理页看到原始图鉴面板。通知页同时显示实时活动和闹钟预览，游戏运行页保留上游启动检查。验证在独立安装中进行，未登录游戏账号。
- 完整版的英文卡片、图鉴控制器、Widget、WebGL 脚本及相应 Swift 桥接与原发布分支逐文件一致。AlarmKit 实现与上轮已验证提交一致。两个本地依赖已分别对照官方归档，运行时源码各只有一个原生文件发生修改。

## 先前 1.10 适配的验证记录与设备限制

- **静态分析与构建**　Flutter 3.47.9 对本次改动的七个 Dart 文件报告 0 个问题。使用 `lib/main_ios.dart` 完成 iOS 真机架构的无签名 Release 构建和模拟器 Debug 构建。Release 产物的最低系统版本为 15.0，通知设置跳转和 iOS 17 代理的高版本符号均为弱链接。
- **模拟器实测**　在既有 iPhone 18 Pro（iOS 27.2）上，用单独的应用标识冷启动。拒绝系统通知请求后，通知页显示授权未取得、本地投递说明、五类提醒时间和实时活动入口。页面没有出现精确闹钟、通知渠道或三项状态计数。在「游戏运行」确认启动检查默认开启，在「数据管理」确认 WebKit 缓存说明、浏览器缓存清理和文件备份入口。
- **超时归属**　新的 decoupled WebView 静态分析通过，其无签名 Release 编译通过。build 40 与原发布分支的 Git 文件树仍完全相同。
- **AlarmKit 预览**　1.10 预览改动涉及的三个 Dart 文件静态分析为 0 个问题。无签名 Release 和模拟器 Debug 均已编译。Release 中 AlarmKit 是弱链接，最低系统版本为 iOS 15.0，产物包含五种语言的闹钟用途说明。在 iPhone 18 Pro（iOS 27.2）临时安装中确认预览默认关闭。手动开启触发独立的 AlarmKit 请求。该模拟器的 SpringBoard 拒绝系统进程 mobiletimerd 显示授权提示，应用正确显示「前往 iOS 设置允许闹钟」。已验证拒绝路径，实际授权后的锁屏响铃、专注／静音模式表现和任务撤销仍待设备验证。
- **待真机或账号验证**　尚未实测完整登录与战斗结算、故障网络下的重试、锁屏通知在预定时间的投递、从旧备份实际恢复，以及 iOS 15 和旧 iPad 的运行表现。
