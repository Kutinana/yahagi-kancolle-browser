# Yahagi v1.0.5 Beta 发布实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 构建可覆盖 `1.0.4` 且保留游戏资源缓存的 `1.0.5-beta.1` 正式签名 APK。

**架构：** 沿用现有 Android 应用 ID、正式签名配置和私有缓存路径，只递增 Flutter 包版本及两个网络更新服务的 User-Agent 版本。构建后同时检查 APK 清单和签名证书，并在有设备时执行原位升级缓存核验。

**技术栈：** Flutter、Dart、Android Gradle Plugin、Android `aapt`、`apksigner`、ADB

---

### 任务 3：核验升级身份和缓存兼容性

- [ ] **步骤 1：检查 APK 清单**

运行：

```powershell

```

预期：包名为 `app.yahagi.kancollebrowser`，`versionName` 为 `1.0.5-beta.1`，`versionCode` 为 `6`。

- [ ] **步骤 2：比较新旧签名证书**

分别对新 APK 和 `Yahagi-v1.0.4.apk` 运行：

```powershell

```

预期：两者的证书 SHA-256 均为 `ea33c5f1e06f615fe480463bbac7c1155bc3107bea47b6db706833378019c482`。

- [ ] **步骤 3：检查缓存路径未改变**

运行：

```powershell

预期：仍命中 `File(filesDir, "game_resource_cache")`。

- [ ] **步骤 4：如有设备，执行原位升级验证**

```

预期：输出 `Success`，升级后的缓存文件数量和总大小不减少。若没有设备，记录为未执行，不把静态兼容检查表述为设备实测。
