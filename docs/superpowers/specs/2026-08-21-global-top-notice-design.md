# 全局顶部胶囊提示设计

## 背景

当前应用通过 `ScaffoldMessenger.showSnackBar` 显示截图结果、游戏框架重载结果、设置保存结果和错误信息等临时反馈。这些提示默认出现在页面底部，与应用顶部已有的胶囊式导航视觉不一致；在游戏界面中，底部提示还容易遮挡游戏内容。

本次调整将应用自身产生的所有临时提示统一迁移到顶部胶囊区域。用户已明确不需要可视化原型，直接按现有顶部胶囊风格实现。

## 目标

- 应用自身的临时提示全部显示在顶部胶囊区域，不再从底部弹出。
- 提示以悬浮层呈现，不推动页面、游戏画面或顶部工具栏重新布局。
- 保留现有提示文案、提示时长和成功/错误语义。
- “截图成功”“游戏框架未能重新载入”“当前设备的 Android WebView 太旧，不支持对子框架注入”等提示遵循同一套规则。
- 建立统一入口，避免后续功能重新直接调用底部 `SnackBar`。

## 范围

### 包含

- `lib/` 下所有由应用主动触发的临时文字反馈。
- 当前直接调用 `ScaffoldMessenger.showSnackBar` 的截图、游戏框架重载、渲染模式、资源缓存、网络设置、数据设置、诊断和关于页面等场景。
- 中性、成功和错误三种提示语义。
- 相关组件测试和“禁止新增直接 SnackBar 调用”的契约测试。

### 不包含

- Android、WebView、系统或第三方组件自行显示的系统提示。
- 确认对话框、设置对话框、加载遮罩、进度指示器和需要用户持续处理的错误页面。
- 带操作按钮的通知、通知历史或消息中心。
- 顶部导航栏本身的视觉重做。

## 交互设计

### 位置与尺寸

- 提示在应用可用视口顶部水平居中，视觉中心与现有顶部胶囊行对齐。
- 定位必须纳入 `MediaQuery.padding.top`，避开刘海、挖孔和系统状态栏安全区。
- 提示覆盖在页面和顶部工具栏之上，但不改变任何现有布局尺寸。
- 胶囊左右至少保留 16 逻辑像素的屏幕边距，最大宽度为 720 逻辑像素。
- 短文案单行显示；长文案最多两行，胶囊从顶部区域向下扩展，不截断关键错误原因。
- 提示没有交互按钮，因此使用 `IgnorePointer`，不额外拦截顶部控件的点击。

### 视觉语义

- 圆角、内边距、阴影和字体层级与现有顶部胶囊风格保持一致。
- 中性提示和成功提示沿用顶部胶囊的常规深色背景；成功语义可使用现有成功色图标或前景强调色。
- 错误提示使用现有错误红色体系，保证与普通提示有明显区分。
- 文本颜色必须满足可读性要求，不依赖颜色作为唯一语义提示。

### 展示规则

- 同一时间只展示一条提示。
- 新提示到达时立即替换旧提示，并重新计算自动消失计时。
- 默认时长沿用 Flutter `SnackBar` 的现有默认值 4 秒；已有调用显式指定时长时继续使用该时长。
- 截图流程中的“正在保存”和最终结果属于连续状态，最终结果直接替换进行中提示。
- 提示出现和消失采用轻量淡入淡出与纵向位移动画，不影响页面布局。
- 无障碍层将提示标记为 `liveRegion`，使屏幕阅读器能够播报最新内容。

## 技术设计

### 组件结构

新增一套应用级顶部提示组件：

- `TopNoticeHost`：在应用壳层根部挂载一次，负责悬浮层、定位、动画、计时器和生命周期。
- `TopNoticeController`：保存当前提示状态，保证“最新提示替换旧提示”的单实例行为。
- `TopNotice`：面向业务代码的统一调用入口，通过调用处的 `BuildContext` 查找最近的 Host。
- `TopNoticeTone`：定义 `neutral`、`success`、`error` 三种语义，不允许业务代码自行拼装颜色。

建议的业务调用形式为：

```dart
TopNotice.show(
  context,
  message: message,
  tone: TopNoticeTone.error,
  duration: const Duration(seconds: 4),
);
```

Host 使用应用根部 `Stack` 中的 `Positioned`/`AnimatedSwitcher` 悬浮层实现，而不是 Material `SnackBar`。这样可以稳定锚定顶部胶囊行，并避免 `ScaffoldMessenger` 的 Scaffold 层级、浮动按钮和底部安全区影响位置。

### 挂载位置

- `TopNoticeHost` 挂载在主应用壳层中，并覆盖主 Navigator 的普通页面内容。
- 设置页等现有应用页面共享同一个 Host，因此业务页面无需重复声明容器。
- 模态对话框和系统路由仍保持更高层级；由对话框触发的结果提示应在对话框关闭后展示。
- 若调用上下文中找不到 Host，调试构建给出清晰断言信息，发布构建安全返回，避免提示功能导致业务崩溃。

### 状态与生命周期

- Controller 每次展示时生成新的提示标识，取消旧计时器并启动新计时器。
- 旧计时器即使晚到也不能关闭更新后的提示。
- Host 销毁时必须取消计时器和动画资源。
- 文案只保存为当前状态，不维护历史记录。

### 迁移策略

1. 先实现 Host、Controller、统一 API 和基础组件测试。
2. 在应用壳层挂载唯一 Host。
3. 将 `lib/` 下现有直接 `ScaffoldMessenger.showSnackBar` 调用逐一迁移到 `TopNotice.show`。
4. 根据现有语义映射提示类型：普通状态为 `neutral`，明确成功结果为 `success`，失败和异常为 `error`。
5. 删除迁移后不再使用的 `SnackBar` 专用代码，并更新受影响测试。

## 测试设计

### 组件测试

- 提示显示在视口顶部区域且水平居中，不位于底部。
- 提示尊重顶部安全区。
- 默认时长结束后自动消失。
- 新提示替换旧提示，旧计时器不会误删新提示。
- 错误提示应用错误语义样式，中性/成功提示使用对应样式。
- 长文案最多两行，并在窄屏下保持左右安全边距。
- 提示层不推动底层布局，也不拦截底层点击。
- Host 销毁后没有悬挂计时器或测试异常。

### 业务回归测试

- 截图保存过程和成功/失败结果均显示为顶部提示。
- 游戏框架重载成功、普通失败和 Android WebView 过旧提示均显示在顶部。
- 设置、缓存、网络、数据和诊断页面原有临时反馈仍能显示，文案与时长不变。
- 对话框、加载状态和持久错误展示方式不受影响。

### 契约测试

增加源码契约检查，扫描 `lib/` 并禁止业务代码直接出现 `ScaffoldMessenger.showSnackBar` 或构造 `SnackBar`。统一提示组件内部也不依赖 `SnackBar`。这项测试用于阻止后续功能重新引入底部提示。

## 验收标准

- 应用内现有临时提示全部从底部迁移到顶部胶囊位置。
- 任一时刻最多展示一条提示，新提示可靠替换旧提示。
- 提示不会引起游戏画面、页面内容或顶部工具栏位移。
- 在常规屏幕、窄屏和带顶部安全区的设备上均可完整阅读。
- Android WebView 过旧提示能完整表达“不支持对子框架注入”的原因。
- `lib/` 中不存在绕过统一入口的直接 SnackBar 调用。
- 新增测试通过，现有相关功能测试无回归。

## 风险与处理

- **顶部空间拥挤**：通过最大宽度、两行限制和安全区计算控制占用；提示自动消失且不改变布局。
- **连续提示互相覆盖**：统一 Controller 采用最新消息优先，并使用提示标识隔离旧计时器。
- **页面层级找不到 Host**：Host 固定挂载在应用壳层，调试断言辅助发现遗漏上下文。
- **迁移遗漏**：源码契约测试与全局检索共同保证 `lib/` 内没有直接 SnackBar 调用。
