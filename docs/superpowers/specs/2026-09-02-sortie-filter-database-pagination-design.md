# 出击记录筛选数据库分页设计

## 背景

航海日志的出击记录按每批 50 条分页加载。当前筛选面板直接从页面已加载的 `_records` 提取海域和状态候选项，因此首次打开时只能看到最近一批记录包含的海域。筛选后表格行数减少，滚动组件可能继续加载旧记录，导致第二次打开筛选时出现更多候选项，形成不稳定的使用体验。

同一问题还会让筛选结果只覆盖已加载记录。即使筛选面板能显示某个历史海域，页面也不能保证已经加载该海域的明细。

## 目标

- 首次打开筛选面板时，显示数据库中全部历史出击涉及的海域和状态。
- 选择历史海域、状态、评价或日期后，从数据库查询匹配记录，而不是只筛选当前页面数据。
- 筛选后的明细继续按每批 50 条分页加载。
- 页面只缓存体积很小的筛选目录，不预加载全部出击明细。
- 新增出击或资源点记录后，筛选目录和当前结果能够刷新。

## 非目标

- 不修改数据库表结构或迁移版本。
- 不改变筛选面板的视觉样式和交互布局。
- 不重做其他航海日志分类的筛选逻辑。
- 不把“共 N 条”改成数据库总数；本次仍表示当前已加载且匹配的行数。

## 根因

`_LogbookTablePageState._filterFields` 使用 `_records.map(...)` 生成动态候选项，而 `_records` 只保存已分页加载的数据。`_matchesFilter` 也只在 `_records` 上运行。因此，筛选目录和筛选结果都错误依赖了表格的局部分页状态。

## 方案

### 1. 独立筛选目录

在 `LogbookDatabase` 增加轻量查询，从 `battle_logs` 和 `map_resource_logs` 中联合读取并去重以下字段：

- `map_area`
- `map_no`
- `map_name`
- `map_difficulty`
- 记录类型和 `node_type` 所表达的状态

查询不读取舰队、掉落或 JSON 明细。页面把海域元数据交给现有 `_formatMapLabel` 生成显示文本，并建立“显示文本 → 一个或多个海域身份”的映射。这样既能复用历史名称和当前母港主数据，也能兼容多个元数据组合最终显示为同一文本的情况。

筛选目录在出击页面初始化时异步加载并保存在页面状态中。数据库发出 battle 变更通知时重新加载目录。打开筛选面板时若目录仍在加载，则等待该轻量查询完成后再展示，确保首次打开就是完整目录。

### 2. 数据库筛选与分页

为 `getSortieRecords` 增加可选查询条件：

- 日期下限时间戳
- 海域身份集合
- 出击状态
- 评价

查询继续使用现有的 battle/resource 联合结果，在联合子查询外追加 `WHERE` 条件，再按 `timestamp DESC, id DESC` 排序并执行 `LIMIT/OFFSET`。

状态筛选规则：

- “资源获得”匹配 `record_type = 'resource'`。
- 其他状态匹配 `record_type = 'battle' AND node_type = ?`。
- 评价只匹配 battle 记录；资源记录的 `unknown` 不会进入正式评价候选。

### 3. 页面状态切换

应用或重置筛选时：

1. 更新 `_filters`。
2. 清空当前 `_records`。
3. 将 `_hasMore` 恢复为 `true`。
4. 从数据库加载筛选后的第一页。

后续滚动仍调用 `_loadMore`，但携带同一组数据库条件。刷新最新记录时也沿用当前条件。

使用查询代次标识防止旧的异步请求在筛选条件切换后把过期结果追加回来。数据库变更导致目录刷新时，如果当前选中的海域已经不存在，则回退到“全部海域”。

## 错误处理

- 筛选目录查询失败时不破坏现有表格；面板保留“全部海域”和固定评价选项。
- 数据库查询返回空集合时显示现有“暂无记录”状态。
- 空名称仍通过现有母港地图主数据或海域编号生成有效标签。
- 演习继续使用 `map_area = 0`、`map_no = 0` 和“演习”标签。

## 测试设计

### 数据库测试

- 最近 50 条只包含少数海域、旧记录包含其他海域时，筛选目录仍返回全部去重海域。
- battle 和 resource 表中相同海域不会生成重复候选。
- 日期、海域、状态和评价条件分别正确过滤联合记录。
- 筛选查询仍按 50 条分页，第二页不重复、不遗漏。

### Widget 测试

- 插入超过 50 条记录后，首次打开海域筛选即可看到首批之外的历史海域。
- 选择该历史海域并应用后，表格显示对应旧记录，而不是“暂无记录”。
- 新增一个此前不存在的海域后，再次打开筛选即可看到它。
- 状态候选来自完整历史目录，不依赖当前屏幕已加载行。

### 回归测试

- 未启用筛选时保持现有分页行为。
- 重置筛选后恢复最近记录。
- 其他航海日志分类的筛选和分页不受影响。

## 验收标准

- 无论当前屏幕加载了多少条记录，首次打开海域筛选都能看到所有曾经记录过的海域。
- 选择任意历史海域后能够立即显示匹配的第一页，并可继续滚动加载。
- 不把全部出击明细加载进内存。
- 相关数据库测试、Widget 测试和航海日志回归测试全部通过。
