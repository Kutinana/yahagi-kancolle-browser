# POI 全量重放战斗预测引擎设计

## 背景

Yahagi 目前有两套战斗预测引擎：默认的 POI 引擎和可选的 Yahagi 引擎。本次只重写默认 POI 引擎，设置入口和 Yahagi 引擎保持不变。

现有 POI 引擎虽然移植了部分伤害解析规则，但仍按收到的数据包增量修改当前 HP。POI 的实际做法不同：它保存开战时舰队和本场全部战斗数据包，每收到一个新阶段就从初始状态重新建立模拟器，并按 API 路径规定的阶段顺序重放全部数据包。增量状态、阶段归属和舰队边界一旦有一项判断错误，后续夜战就会在错误 HP 上继续计算。

友军舰队是游戏在特定海域提供的 NPC 舰队，不是玩家的远征支援。现有实现没有独立的 NPC 友军舰队模型，容易把 `api_friendly_battle` 或 `api_friendly_kouku` 的友方伤害字段映射到玩家舰队。联合舰队、游击部队七舰和夜战同时出现时，这种隐式索引判断风险最高。

## 目标

- 默认 POI 引擎改为“不可变初始快照 + 全部数据包历史 + 每次完整重放”。
- 按 POI `lib-battle` 的 API 路径、舰队类型和阶段顺序执行战斗。
- 独立建模 NPC 友军舰队，友军航空战和友军夜战不得扣玩家 HP，也不得计入玩家 MVP。
- 使用保留空位和原始位置的舰队槽位，正确处理六舰、七舰游击部队、联合舰队和敌联合舰队。
- 伤害控制人员和女神按实际装备顺序单次消费；重放时从开战装备状态重新计算，不重复消费旧状态。
- 战果等级、MVP 和 HP 与 POI 对有效数据保持一致；服务器明确结果优先。
- 对未知路径、缺失关键字段或非法目标采取关闭式失败：保留可确认的 HP，添加解析问题，并把预测标为“未确认”，不输出有把握但错误的沉船结论。

## 非目标

- 不删除或重写 Yahagi 预测引擎。
- 不改变战斗预测设置和界面布局。
- 不把远征支援与 NPC 友军舰队合并成同一概念。
- 不使用战果 S/SS 反推具体剩余 HP。
- 不承诺自动理解未来新增且尚未记录的 API 阶段；未知阶段必须显式暴露为未确认。

## 总体架构

### 重放包装器

`PoiBattlePredictionEngine` 继续实现现有 `BattlePredictionEngine` 接口，但内部不再长期持有已受伤的可变舰队：

1. 构造时深拷贝玩家主力、玩家随伴、敌主力、敌随伴和联合舰队类型。
2. `append(path, data)` 深拷贝并追加一个不可变战斗包。
3. 为本次计算创建新的 `PoiBattleSimulator`。
4. 从初始舰队依次重放所有历史包。
5. 从模拟器最终状态生成 `BattlePrediction`。

因此同一历史始终产生同一结果；前一轮预测对象中的 HP、损管消费或解析问题不会泄漏到下一次计算。

### 模拟状态

模拟器内部使用可空槽位而不是先过滤舰船的紧凑列表：

- 玩家主力：按实际槽位保存，允许游击部队第 7 舰。
- 玩家随伴：联合舰队随伴槽位。
- 敌主力和敌随伴：分别保存，保留原 API 位置。
- NPC 友军：由 `api_friendly_info` 创建独立槽位，只作为攻击者参与友军阶段。

每艘舰保存初始 HP、当前 HP、累计承伤、累计输出、原始位置、损管装备及消费状态。输出时过滤空槽，但保留 `position`，因此“列表下标”和“舰队位置”不再混用。

### 路径驱动的阶段调度

模拟器按精确 API 路径分发，不再只凭数据包里出现哪些键就统一执行日战和夜战。每种路径声明允许出现的阶段及固定顺序，包括：

- 通常舰队日战、夜战、夜转日和航空战。
- 联合舰队四种交战组合及其不同炮击顺序。
- 游击部队七舰。
- 开幕反潜、开幕雷击、炮击、闭幕雷击。
- 基地航空队、喷气阶段、通常航空战和支援舰队。
- 夜间支援、夜间特殊炮击、NPC 友军夜战和玩家夜战。

阶段顺序以 POI 当前 `lib-battle` 实现为基准；不依赖 JSON 键顺序。

## 目标与伤害路由

每次攻击先确定四个维度：攻击阶段、攻击方、攻击方舰队、目标舰队。目标编号仅在确定舰队后解释。

- 有 `api_at_eflag` / `api_active_deck` 时优先使用服务端字段。
- 缐少攻击方标志时，仅在当前阶段语义能够唯一确定时回退推断。
- 七舰游击部队使用本场主舰队实际长度作为边界；联合舰队固定槽位编码只在对应路径使用。
- 非零伤害命中不存在槽位、舰队编号矛盾或长度不一致时记录 `BattleParseIssue`，不把目标折算到旗舰或敌舰。
- 多段伤害先按一次攻击聚合，再结算一次击沉和损管，避免同一连击重复触发。

## NPC 友军舰队

`api_friendly_info` 只初始化 NPC 友军攻击者，不进入玩家主力或玩家随伴。随后：

- `api_friendly_kouku` 中友军承伤字段作用于 NPC 友军；敌方承伤字段作用于敌舰。
- `api_friendly_battle.api_hougeki` 的攻击者来自 NPC 友军，目标只允许敌方主力或随伴。
- NPC 友军造成的输出不计入玩家 MVP。
- 玩家舰队 HP 只能由敌方攻击字段改变。
- 缺失可安全推断的友军攻击方标志时，阶段类型固定为 NPC 友军对敌；出现互相矛盾的明确字段时标记未确认。

## 损管语义

损管状态属于一次模拟器实例。舰船受到致命伤害时：

1. 查找尚未消费且装备顺序最靠前的损管。
2. 要员恢复最大 HP 的 20%，至少 1 HP；女神恢复最大 HP。
3. 标记该道具已消费；本次重放的后续致命攻击不能再次使用同一件道具。
4. 下一次 `append` 会从初始装备重新重放全部阶段，所以历史致命伤害仍只消费一次，不受上一模拟器残留状态影响。

这保持 POI 的重放架构，同时保留 Yahagi 已修正的“同一件损管不能跨多个致命阶段反复使用”规则。

## 等级、MVP 与确认状态

- 战果等级使用 POI 的沉船数和损血率规则，包括 9、10、11 舰敌编成的半沉阈值。
- 玩家完全无损时允许 SS；女神恢复到初始 HP 以上时按 POI 使用非正损失判断。
- HP 未知的敌舰不参与可确认的沉船率；无法安全计算时返回 `BattleRank.unknown`。
- MVP 只统计玩家主力/随伴造成的伤害，保留联合舰队夜战的所属舰队规则。
- 解析问题随预测返回；界面显示“未确认”，而不是用错误目标继续计算。

## 测试策略

### 单元测试

- 相同初始快照和数据包历史重复重放结果完全一致。
- 两个连续数据包不会因旧模拟状态而重复扣血或重复消费损管。
- 六舰和七舰的 0～6 号位置逐船受伤，验证第 7 舰不落入敌舰或旗舰。
- 联合舰队四种类型、`api_active_deck` 主力/随伴组合及敌联合舰队目标路由。
- NPC 友军航空、夜战、多目标攻击、缺失可推断标志和非法冲突字段。
- 要员、女神、多段致命伤害、不同阶段连续致命伤害。
- 敌舰数量 1～12 的等级边界，重点覆盖 9～11 舰。
- 未知阶段和非法目标返回未确认。

### POI 对照测试

- 对现有 303 份 `lib-battle` fixture 逐包调用 Dart 引擎和官方 POI JS 模拟器。
- 每收到一个包就比较双方主力/随伴 HP、等级和 MVP，不只比较战斗最终值。
- 单独统计友军、联合舰队、夜转日、航空、支援、损管和七舰覆盖率，避免“测试全过但场景未覆盖”。

### E4 回归测试

由于现有诊断包关闭了完整 API body，无法从截图精确恢复该场 E4 数据。使用与截图结构一致的合成用例覆盖“我方联合舰队 + 敌联合舰队 + NPC 友军 + 入夜”组合；实现完成后保留接入真实完整包的 fixture 入口。不能把合成测试描述成对截图原场战斗的逐字段复现。

## 成功标准

- 新增回归测试在旧增量实现上能够失败，在重放实现上通过。
- POI fixture 逐包对照无差异；若存在服务器已知规则差异，必须记录并由专门测试固定。
- 战斗预测相关测试和静态分析通过。
- 全仓测试若受仓库缺失夹具影响，明确列出基线失败；不得把基线装配错误算作引擎通过或失败。
- 变更在隔离分支提交，验证后合并到 `master`，不覆盖 master 上用户已有未提交改动。
