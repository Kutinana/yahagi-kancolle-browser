# 出击制空状态跨昼夜战保留设计

## 背景

当前每收到一个战斗阶段数据包，都会重新解析
`api_kouku.api_stage1.api_disp_seiku`。夜战数据包通常不包含航空战字段，
因此昼战已经取得的制空状态会被覆盖为「未知」，并最终写入出击记录。

POI 会在同一场战斗中连续累积昼战和夜战数据包。Yahagi 的制空状态也应采用
战斗会话级语义，而不是单个数据包级语义。

## 已确认方案

- 新节点开始时，制空状态默认为「未知」。
- 当前数据包包含 `0` 至 `4` 的合法 `api_disp_seiku` 时，更新制空状态。
- 当前数据包缺失该字段、无法解析或值超出范围时，沿用本场战斗此前的有效值。
- 夜战转昼战后若出现新的合法值，以新值为准。
- 整场战斗从未出现合法值时，最终记录「未知」。
- 不修改历史数据库记录，不推断过去未知记录的真实状态。

## 数据流

1. `BattleController` 解析当前战斗阶段的 `api_disp_seiku`。
2. 合法值映射为均衡、确保、优势、劣势或丧失。
3. 非法或缺失值从当前战斗对象继承上一阶段状态。
4. 战果到达后，`BattleRecord` 保存最终保留的状态。
5. `LogbookDatabase` 按现有逻辑持久化，航海日志按现有逻辑显示。

## 测试范围

- 昼战取得「优势」后进入无航空字段的夜战，仍保持「优势」。
- 单独夜战或整场无航空字段时仍为「未知」。
- 合法状态映射、数据库持久化和航海日志显示的既有测试继续通过。
