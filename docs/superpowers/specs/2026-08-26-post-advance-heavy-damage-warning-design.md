# 大破进击后提醒时序设计

## 背景

当前 `BattleResultWarningOverlay` 在收到非 Boss 节点的 `/battleresult` 后立即弹出“大破安全警告”。此时游戏通常仍在显示战斗结束或战果演出，提醒过早并打断结果查看。

用户希望采用与 poi 类似的事件驱动时机：战果阶段只记录风险；只有用户随后选择“进击”，游戏返回 `/api_req_map/next` 后才弹出警告。选择撤退时不弹出。该方案不轮询或识别游戏画面，因此没有持续检测开销。

## 目标行为

1. 收到出击或联合舰队战果后，判断当前是否存在进击风险：
   - 当前节点不是 Boss 终点；
   - 友军中存在未退避的大破舰。
2. 存在风险时只记录一条“待进击提醒”，不弹窗、不触发战后提醒震动。
3. 随后收到 `/kcsapi/api_req_map/next` 成功响应时：
   - 若存在待进击提醒且设置为开启，立即消费该提醒；
   - 弹出一次大破进击警告；
   - 若战斗受损震动已开启，触发一次 `postBattleWarning` 震动（当前波形为单次约 300 ms）。
4. 收到撤退回港接口、母港接口或新的战果时，清理或覆盖旧的待提醒状态，避免跨出击误报。
5. 同一个战果风险最多触发一次进击提醒；重复事件或弹窗关闭后不再次提醒。

## 震动语义

- 保留战斗过程中舰娘刚进入中破或大破时的现有受损震动。
- 战果阶段不再额外震动。
- 用户带着待处理的大破风险选择进击后，弹窗出现时额外震动一次。
- 关闭“战斗受损震动提醒”后，两类震动都不触发，但弹窗仍由“大破提醒”开关控制。

## 提醒文案

现有“继续进击前”文案不再符合新时机。中文提示改为明确的事后警告语义，例如：

> 已在大破状态下选择进击！请立即停止后续操作，避免进入下一场战斗。

日文与繁体中文同步更新，按钮仍使用“确认了解”一类纯确认操作。弹窗不会声称能够撤销已经完成的进击请求。

## 数据流

```text
/battleresult
  -> BattleController 完成战果与舰队伤害计算
  -> BattleResultWarningOverlay 判断是否存在非 Boss 大破风险
  -> 仅保存 pendingAdvanceWarning

/api_req_map/next
  -> GameCaptureController 发布成功响应
  -> 若 pendingAdvanceWarning 存在：原子消费
  -> 可选单次震动
  -> 显示大破进击警告

/goback_port 或 /api_port/port
  -> 清除 pendingAdvanceWarning
```

## 边界与失败处理

- `BattleWarningMode.off`：不显示弹窗，并在进击事件到达时消费待提醒，防止以后开启设置导致旧风险误报。
- Boss 终点：不建立待提醒，因为没有后续进击选择。
- 已退避舰：不计入风险，与现有规则一致。
- 震动通道失败：只记录调试日志，不阻止弹窗。
- 弹窗路由已存在或组件已经卸载：不得重复展示或访问无效上下文。
- 本次设计不拦截或撤销 `/api_req_map/next`；提醒发生时服务器已经接受进击，文案必须如实说明。

## 测试范围

- 非 Boss 大破战果不会立即弹窗或触发 `postBattleWarning` 震动。
- 风险战果后的 `/api_req_map/next` 只弹一次并只震一次。
- 撤退接口会清除待提醒，之后的事件不误报。
- Boss、无大破、已退避舰与关闭提醒模式均不弹。
- 关闭震动时仍显示弹窗，但不调用震动端口。
- 连续战果会用最新风险覆盖旧状态，不跨出击触发。
- 原有战斗中中破/大破受损震动测试保持通过。

## 非目标

- 不轮询截图、不做 OCR 或 Canvas 图像识别。
- 不在用户点击进击前识别“进击 / 撤退”按钮。
- 不暂停、重放或撤销游戏网络请求。
- 不改变其他制空、索敌、远征等弹窗的原生图层处理。
