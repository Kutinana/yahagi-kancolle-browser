# 出击记录战斗详情设计

## 目标与范围

Yahagi 从本功能上线后自动捕获并保存每场新战斗的详情。在「航海日志 → 出击」中点击战斗记录整行，打开与现有 Yahagi 深蓝、金色强调风格一致的战斗详情页，用 POI 战斗详情相同的信息方向还原双方舰队和逐次攻击过程。

本功能不导入旧 POI JSON，不回填历史 Yahagi 记录，不在战斗结束时自动弹出。资源节点等非战斗记录不可点击。详情页不提供「结算」或「原始数据」页签，也不显示战斗阶段侧边栏。

## 进入与返回

- 出击表格的战斗行整行可点击，并保留键盘/读屏按钮语义。
- 点击后在日志工作区内切换到详情视图，保留应用顶部资源栏和主导航。
- 详情首屏显示返回按钮、海域/节点、完成时间和评价；不重复展示联合舰队类型、阵型、制空、交战形态等左侧摘要块。
- 返回后仍停留在出击页，保留筛选条件、已加载记录和表格滚动位置。
- 新功能只对包含 `detail_json` 的新战斗启用；旧记录保持普通不可点击行，避免展示伪造过程。

## 数据快照

在战果 API 到达、确认最终 `LiveBattle` 后，从当前 `BattleSession` 的完整战斗包和战斗开始时舰队快照生成一个版本化 `BattleDetailSnapshot`，与出击记录写入同一行。

快照包含：

- 元信息：格式版本、开始/结束时间、海域与节点、评价、敌舰队名。
- 四支舰队：我方第一舰队（主力）、我方第二舰队（随伴）、敌方主力、敌方随伴。
- 每舰：阵营、舰队角色、位置、舰名、舰娘等级（我方可得时）、初始/最大/最终 HP、造成/承受伤害、装备名称与改修/熟练度。
- 阶段列表：阶段键、中文标题、顺序和攻击行。
- 每次攻击：攻击方和目标的阵营/舰队/位置/舰名、攻击类型、逐段伤害、命中类型、每段伤害后的 HP，以及损管发动信息。

数据库 `battle_logs` 增加可空的 `detail_json`。升级前记录的该字段为空，因此不会被误认为可查看详情。解析失败时仍保存普通出击记录，并让详情为空；捕获链路不能因详情功能阻塞。

## 战斗过程还原

阶段顺序沿用 Yahagi 已验证的 POI 兼容回放顺序：喷气/基地航空队/航空战/支援/开幕反潜/开幕雷击/炮击轮次/雷击/夜战支援/夜战。炮击数据读取 `api_at_eflag`、`api_at_list`、`api_df_list`、`api_damage`、`api_cl_list` 和 `api_sp_list`；空袭、雷击和支援按舰位生成可归属的伤害行。

联合舰队的绝对舰位必须映射到正确的主力或随伴舰队，敌方对我方造成的伤害与我方对敌方造成的伤害使用同一事件模型。多段攻击不得合并：每段伤害、暴击/命中/未命中和段后 HP 均需保留。

如果 API 阶段只有目标伤害而没有可确定的攻击舰，攻击方显示阶段来源（例如「航空战」或「支援舰队」），目标和 HP 仍须准确。损管消耗按现有战斗回放结果附着到触发的攻击行。

## 详情界面

详情只有两个页签：

1. 「舰队」：左右对比。我方固定在左，敌方固定在右；上下依次是主力和随伴。卡片显示舰位、舰名/等级、HP 条、初始→最终 HP、造成/承受伤害和装备摘要。没有随伴舰队时显示克制的空状态。
2. 「战斗过程」：按阶段分组的全宽时间线。顶部提供「全部 / 我方攻击 / 敌方攻击」筛选。阶段标题内联显示，可折叠；没有独立阶段侧栏。

宽屏攻击行使用 POI 的七列方向：`我方 HP | 我方舰名 | ← | 攻击类型与逐段伤害 | → | 敌方舰名 | 敌方 HP`。我方攻击点亮右箭头并更新右侧敌方 HP；敌方攻击点亮左箭头并更新左侧我方 HP。窄屏改为上下两层卡片，第一层呈现攻击者→目标，第二层呈现攻击类型、逐段伤害和双方 HP，禁止横向滚动。

## 响应式边界

- 普通手机横屏（约 915×412）：头部压缩为单行，内容保持可纵向滚动；舰队卡片使用紧凑双列。
- 折叠屏（约 914×836）：保持双侧舰队对比和全宽战斗过程。
- 平板横屏（约 1280×800）：扩大列间留白，不增加阶段侧栏。
- 平板竖屏（约 800×1280）及普通手机竖屏：舰队对比改为我方/敌方分段，攻击行改为两层卡片。

所有尺寸必须避免 RenderFlex 溢出和不可见的横向内容。触控目标至少 40 逻辑像素，颜色之外同时以箭头、标签和文字区分阵营与命中状态。

## 验证标准

- 新捕获的战斗写入可反序列化详情；旧记录为空且不可进入。
- 联合舰队能正确区分四支舰队；敌方攻击能显示我方段后 HP。
- 多段伤害保持逐段数据和最终 HP 一致。
- 点击出击战斗行进入详情，返回后筛选和表格状态仍在。
- 详情只出现「舰队」「战斗过程」，不存在「结算」「原始数据」和阶段侧栏。
- 915×412、914×836、1280×800、800×1280 四种测试尺寸无布局异常。
- 运行相关 Flutter 单元/组件测试和 `flutter analyze`；不执行 debug APK 构建。
