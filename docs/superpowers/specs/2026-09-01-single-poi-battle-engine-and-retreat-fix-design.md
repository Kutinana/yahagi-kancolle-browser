# 单一 POI 战斗引擎与退避修复设计

## 背景

Yahagi 当前同时保留 POI 全量重放引擎和 Yahagi 轻量增量引擎。两套实现已经出现语义分叉：轻量引擎会把 NPC 友军航空伤害计入玩家舰队，并可能在友军夜战缺少攻击方标志时反转攻击方向。错误结果还会写回全局舰船 HP。

舰队司令部退避另有独立错误：战果包中的 `api_escape_idx` 和 `api_tow_idx` 是候选数组，当前实现却把数组内所有位置都记为实际退避。POI 只采用每个数组的第一个选择项，因此本次 E5 场景中一艘大破舰回归会被 Yahagi 错误显示为四艘退避。

用户已确认移除轻量模式和设置中的引擎切换。此后产品只使用 POI 兼容引擎。

## 目标

- 运行时只存在一个 POI 兼容战斗预测路径。
- 删除轻量模式设置入口、持久化选择和旧引擎实现。
- 旧用户即使保存过 `yahagi`，升级后也无条件使用 POI，并清理旧设置值。
- 修正舰队司令部退避：每个候选数组只采用第一个有效位置。
- 友军航空、友军夜战和后续玩家 HP 写回继续使用 POI 的独立 NPC 友军语义。
- 用 E5 多候选退避形状和现有友军组合样本建立回归测试。
- 完成针对性测试、POI 304 份语料对照、静态分析和全仓测试。

## 非目标

- 不在本次界面中显示 NPC 友军舰队详情。
- 不改变敌舰预览、上次阵形提示等其他战斗设置。
- 不重写已经通过 POI 语料对照的全量重放模拟器。
- 不根据截图猜测新的服务端字段；缺失的真实新机制语料仍需后续持续补充。

## 方案比较与决定

### 方案 A：彻底统一为 POI 引擎（采用）

删除轻量引擎、旧解析器、引擎枚举和切换界面。所有战斗统一进入 POI 重放引擎。优点是只有一套战斗真相，友军、联合舰队、损管和后续节点不再因模式不同而分叉；代价是失去低性能设备上的简化路径。

### 方案 B：仅隐藏轻量模式

界面不再展示切换，但保留旧引擎和持久化值。改动较小，但旧用户仍可能继续运行已保存的 `yahagi`，后台代码也会继续腐化，不能解决根因。

### 方案 C：保留轻量引擎作为自动回退

POI 引擎异常时自动切换轻量引擎。该方案会把“明确未确认”变成“静默使用已知错误结果”，并可能继续污染玩家 HP，因此不采用。

## 架构设计

### 单一引擎入口

`BattleController` 不再读取预测模式，也不再保存当前引擎类型。创建新战斗会话时始终构造 `PoiBattlePredictionEngine`，测试仍可通过一个 POI 工厂注入替身。

与引擎类型有关的条件分支改为 POI 固定语义：

- 出击时始终启用跨节点损管账本。
- 解析问题或账本不可信时禁止发布玩家 HP。
- 练习战继续不使用出击损管账本，但仍由 POI 引擎解析。
- 未知路径和非法目标继续返回 `BattleParseIssue`，不得回退到轻量猜测。

### 删除旧解析链

删除 `YahagiBattlePredictionEngine` 和 `BattleDamageParser`。`BattleParseIssue` 是 POI 引擎仍需要的公共结果类型，将迁移到预测引擎公共模型中，避免为了一个数据类保留整套旧解析器。

所有只验证已删除实现的测试一并删除；其中仍有价值的阶段、友军和损管场景迁移到 POI 引擎或控制器回归测试。

### 设置迁移与界面

删除 `BattlePredictionMethod`、方法读写接口以及 `battle.predictionMethod` 的运行时读取。首次加载战斗设置时清理这个旧 SharedPreferences 键；清理失败不得阻止应用启动，因为运行时已经没有非 POI 分支。

设置页删除以下内容：

- “战斗预测引擎”分段按钮。
- “增强模式 / 轻量模式”文字。
- 模式推荐和“下一场战斗生效”说明。

敌舰头像预览和上次阵形提示开关保持原样。相应 ARB 文案和生成的本地化字段同步清理，避免留下不可达文案。

## 退避语义

战果包满足 `api_escape_flag > 0` 时：

1. 解码 `api_escape`。
2. 从 `api_escape_idx` 读取第一个有效正整数；若字段是旧式标量则读取该标量。
3. 从 `api_tow_idx` 采用相同规则。
4. 最多得到一个退避舰位置和一个伴随舰位置。
5. 按通常、联合或七舰游击部队的现有位置规则映射为拥有舰 ID。
6. 在 `goback_port` 或下一节点确认后加入 `escapedShipIds`。

数组中的后续元素是候选项，不得写入 `pendingEscapeShipIds`。同一拥有舰 ID 如异常地同时出现在两组中，只保留一次。

## 数据流与错误处理

```text
战斗 API 包
  → BattleController
  → PoiBattlePredictionEngine 保存全部包并从开战状态完整重放
  → NPC 友军独立于玩家舰队
  → BattlePrediction
  → 仅在解析与损管账本可信时发布玩家 HP

战果 api_escape
  → 每组只取首个有效位置
  → pendingEscapeShipIds
  → goback_port / map next 确认
  → escapedShipIds
  → 右侧舰队退避标记
```

任何 POI 解析问题继续使本场结果未确认，并阻止不可信 HP 写回。不得创建第二套简化结果作为兜底。

## 测试策略

### 先失败的回归测试

- E5 形状：`api_escape_idx=[8]`、`api_tow_idx=[9,10,11]`，只允许两艘舰进入 pending 和 escaped。
- 七舰形状：`api_escape_idx=[1,7]`，只采用位置 1，不得把两个候选都标为退避。
- 旧式标量字段仍能正确映射。
- 设置页不存在预测模式分段按钮，但其他两个战斗显示开关仍存在并可保存。
- 旧 SharedPreferences 值为 `yahagi` 时，加载后旧键被清理且控制器只创建 POI 引擎。
- 现有 E4 联合舰队 + NPC 友军航空 + 友军夜战样本不会减少玩家 HP，敌主力和敌护卫目标正确。
- 控制器收到友军包后发布的玩家 HP 与 POI 预测一致，不把 NPC 友军承伤写回玩家舰船。

### 回归范围

- 舰队司令部退避与战后大破警告测试。
- POI 引擎、控制器、跨节点损管和设置页测试。
- 官方 POI JS 模拟器对照的 304 份 fixture、366 个战斗包。
- `flutter analyze`。
- 全仓 `flutter test`。

304 份现有 fixture 对友军航空、夜转昼、实际支援、七舰和退避覆盖不足，因此合成回归测试必须保留；测试输出的覆盖计数不能再被理解为这些机制已有真实语料保证。

## 成功标准

- 代码和设置中不存在可选择或可运行的轻量战斗模式。
- 保存过 `yahagi` 的旧用户升级后无条件运行 POI 引擎。
- E5 多候选数组不再产生四艘退避。
- 友军阶段不会扣除或持久化到玩家舰队的错误 HP。
- POI 304 份语料逐包对照无差异。
- 静态分析和全仓测试无新增失败。
- 代码审查确认没有遗留不可达分支、旧本地化文案或错误测试预期。
