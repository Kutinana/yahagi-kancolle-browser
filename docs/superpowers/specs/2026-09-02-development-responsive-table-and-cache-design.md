# 装备开发自适应表格与状态缓存设计

## 背景

开发公式表格目前按内容固有宽度收缩。宽屏下表格没有填满工具箱内容区，右侧出现大块空白。离开工具箱后，`EquipmentDevelopmentPage` 会从 Widget 树移除，页面内部的 `EquipmentDevelopmentController` 随之销毁；再次进入时，目标装备等状态恢复为默认值。

## 目标

- 开发公式表格复用开发计算器「出货概率」卡片结构。
- 「可用公式」移动到表格卡片标题栏，不再作为卡片外的独立文字。
- 宽屏下卡片和表格填满内容区，列间空间自适应分配。
- 窄屏下保持表格固有最小宽度，并允许横向滚动。
- 页面切换和应用重启后恢复装备开发工作台上次状态。
- 缓存读取或写入失败时不影响装备开发功能本身。

## 表格布局

`DevelopmentRecipeTable` 始终负责完整卡片，而不只负责 `DataTable`。

卡片结构从上到下为：

1. 标题栏：显示「可用公式」。
2. 分隔线。
3. 横向滚动视口。
4. 配方列头和数据行；没有目标或没有结果时显示空状态。

宽度规则：

- 卡片宽度为父级内容区宽度。
- `DataTable` 外使用 `LayoutBuilder` 和 `ConstrainedBox(minWidth: constraints.maxWidth)`。
- 当表格固有宽度小于内容区时，表格至少扩展到内容区宽度。
- 当表格固有宽度大于内容区时，表格保留固有宽度，由横向滚动视口承载。
- 保留现有 `34 px` 表头、`44 px` 数据行、`12 px` 字号、`8 px` 横向边距和 `16 px` 基础列间距。

## 缓存范围

持久化以下状态：

- 工作台模式：开发计算器或开发公式。
- 目标装备 ID 列表，并保留选择顺序。
- 秘书舰开发池及是否跟随当前旗舰。
- 油、弹、钢、铝资源值。
- 配方排序字段和升降序。

搜索词、目标选择器当前分类、滚动位置和最近应用配方的选中高亮不持久化。这些属于临时交互状态，恢复后可由持久化数据重新计算或重新选择。

## 持久化组件

新增 `development_workbench_state_store.dart`：

- `DevelopmentWorkbenchMode`：公开的计算器/公式模式枚举。
- `DevelopmentWorkbenchState`：不可变状态对象，负责 JSON 编解码和默认值。
- `DevelopmentWorkbenchStateStore`：提供 `load()` 与 `save()` 接口。
- `SharedPreferencesDevelopmentWorkbenchStateStore`：使用单个版本化 JSON 字符串保存状态。

页面和 Controller 通过接口依赖 Store，Widget 测试使用内存实现，不依赖平台插件。

## 恢复流程

1. 页面创建 Controller，并传入 Store。
2. Controller 并行准备数据集和缓存状态，数据集可用后再应用缓存。
3. 资源值限制在 `10–300`；非法值回退为默认值。
4. 缓存的开发池不存在时，回退到当前旗舰或首个可用池。
5. 缓存的目标装备不存在或与当前目标组合不兼容时跳过。
6. 恢复排序字段和方向，重新计算出货概率与可用公式。
7. 页面根据 Controller 恢复的模式显示计算器或公式。

缓存解析异常、版本不支持或 Store 读取失败时使用默认状态。异步保存失败只记录调试日志，不回滚当前界面操作。

## 保存时机

以下操作后异步保存快照：

- 切换开发计算器/开发公式。
- 选择或取消目标装备。
- 选择秘书舰开发池或恢复跟随当前旗舰。
- 修改资源值或应用某条配方。
- 修改配方排序。

## 测试范围

- Store 的默认值、JSON 往返、损坏数据回退和 `SharedPreferences` 往返。
- 页面销毁后使用同一内存 Store 重建，恢复模式、目标、资源和排序。
- 数据集中不存在的目标 ID 不会恢复。
- 宽屏下配方卡片与公式内容区同宽，且「可用公式」位于卡片内。
- `390 px` 实际窗口下横向滚动范围大于 `0`。
- 现有配方排序、行点击应用、资源图标语义和目标标签删除行为保持不变。

## 非目标

- 不缓存目标选择器的搜索词和分类。
- 不新增缓存管理或清除按钮。
- 不修改开发概率和配方算法。
- 不安装或自动启动构建出的 Debug APK。
