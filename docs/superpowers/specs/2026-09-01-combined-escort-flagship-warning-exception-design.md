# 联合舰队二队旗舰大破进击提醒例外设计

日期：2026-09-01  
状态：方案 A 已确认

## 背景

战后大破进击弹窗目前会检查 `LiveBattle.friendShips` 中所有未退避的大破舰娘，无法区分联合舰队二队旗舰。联合舰队二队旗舰大破后继续进击不会沉没，因此不应仅因该舰大破而弹出进击警告。

## 目标

- 仅在我方确实以联合舰队出击时，将二队第 1 位舰娘视为进击弹窗的安全例外。
- 二队其他舰、一队舰娘或非联合舰队中的大破舰娘继续触发原有弹窗。
- 二队旗舰与其他危险舰同时大破时，仍然弹窗。
- 保持 Boss 节点、退避舰过滤和设置开关的现有行为。

## 非目标

- 不改变舰队面板中的大破颜色、血量或状态。
- 不改变战斗中首次进入中破或大破时的提醒。
- 不改变航海日志、战斗预测、损管或退避逻辑。
- 不把联合舰队二队全部舰娘视为安全例外。

## 判定规则

战后结果满足现有提醒前提时，逐舰判断是否构成进击风险。仅当舰娘同时满足以下条件时忽略：

1. `battle.context.combinedFleetType != CombinedFleetType.none`；
2. `ship.fleetRole == BattleFleetRole.escort`；
3. `ship.position == 0`。

其中 `position` 使用现有的 0 起始舰队位置，因此 `0` 对应二队旗舰。

最终规则仍是：存在至少 1 艘「未退避、处于大破、且不是上述安全例外」的舰娘时，才挂起进击弹窗。弹窗挂起后的进击、撤退、回港和设置开关流程不变。

## 实现位置

修改 `lib/src/capture/battle_result_warning_overlay.dart` 中的 `shouldShowPostBattleWarning`。安全例外只属于战后进击弹窗，因此不下沉到 `BattleShipSnapshot.isHeavilyDamaged`，也不改动战斗状态模型和预测引擎。

## 测试设计

先增加失败测试，再编写最小实现。至少覆盖：

- 联合舰队仅二队旗舰大破：不提醒；
- 联合舰队二队僚舰大破：提醒；
- 联合舰队一队舰娘大破：提醒；
- 二队旗舰和另一艘舰娘同时大破：提醒；
- 非联合舰队中即使快照标记为二队旗舰，大破仍提醒，防止仅凭角色和位置误判；
- 现有 Boss 节点、退避舰、弹窗只出现一次和设置开关测试继续通过。

回归验证还应包含退避专项、损管生命周期、POI 预测和 POI 原始战斗数据集，确认本次过滤没有进入其他战斗计算路径。

## 风险与控制

- **联合状态误判：** 同时检查 `combinedFleetType`、舰队角色和位置，避免第三舰队或普通舰队被误排除。
- **扩大安全范围：** 只排除 `escort + position 0`，其余大破舰保持原规则。
- **影响战斗展示或预测：** 修改范围限制在弹窗判定函数，不修改模型字段和预测输入。
