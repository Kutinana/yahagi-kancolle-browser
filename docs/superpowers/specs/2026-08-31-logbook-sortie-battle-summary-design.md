# 航海日志出击战斗摘要列设计

## 目标

在航海日志的出击记录中，将「我方阵形」「敌方阵形」「制空状态」「大破舰娘」四列插入「状态」与「评价」之间，并采用已确认的方案 A 语义胶囊样式。

## 数据与持久化

- `battle_logs` 新增我方阵形、敌方阵形、制空状态和大破舰娘 JSON 四个字段，数据库版本从 9 升至 10。
- 战斗结果写入时，从 `LiveBattle` 直接保存双方阵形编号和制空状态；从我方主力、护卫舰队中筛选 `isHeavilyDamaged` 舰娘，按主力后护卫的现有顺序保存舰名。
- 旧数据库升级时使用安全默认值：阵形为 `0`、制空状态为 `未知`、大破舰娘为 `[]`，旧记录在 UI 中显示 `-` 或「未知」。
- 资源节点并无战斗信息，在出击记录联合查询中返回相同默认值，保证 UNION 字段一致。

## UI

- 列顺序固定为：状态、我方阵形、敌方阵形、制空状态、大破舰娘、评价。
- 我方阵形使用绿色语义胶囊，敌方阵形使用红色语义胶囊；阵形编号复用现有 `formationLabel` 映射。
- 制空状态复用现有 `airSuperiorityPillColors` 颜色规则，但胶囊只显示状态文本，不加「制空：」前缀。
- 大破舰娘使用红色粗体文字，多艘以中文顿号「、」分隔；内容过长时自然换行，并按实际文本高度增加该行高度。
- 无阵形、无大破舰娘时显示 `-`，避免把资源节点误认为战斗记录。

## 兼容性与测试

- 数据库测试覆盖新记录写入、联合查询默认值、v9 数据库升级不丢记录。
- Widget 测试覆盖列顺序、方案 A 胶囊颜色与文案、多个大破舰娘顿号分隔和长内容行高。
- 使用现有完整战斗语料测试验证战斗解析没有回归，并运行项目静态分析。
