# 素战果安全累计与手动校正设计

## 目标与范围

修复素战果自动累计可能因较小或乱序经验快照而重复计算累计提督经验的问题，并在「设置 → 数据 → 存储与缓存」提供本月素战果归零和手动填写入口。

本次只调整素战果的经验基准、当月经验记录及相关设置界面。EO、季度/年度/单次任务状态、排名、目标战果、当前战果、出击统计、收藏隐藏和日历中的 EO/任务奖励均不得被清除或重算。

## 自动累计规则

- 素战果公式保持 `提督经验增加量 × 7 / 10000`。
- 新安装、月份切换或旧缓存升级后的第一次有效累计提督经验只用于建立基准，素战果保持 `0.00`。
- 后续累计提督经验严格大于基准时，只把两次累计值的正差换算为素战果并写入对应战果业务日。
- 等于或小于现有基准的经验快照视为重复、乱序或过期数据：忽略该经验值，不增加素战果，也不降低基准。
- 战果日与月份继续以 JST 凌晨 2 点为边界。
- 本月素战果仍为当月所有每日记录中 `experience` 的合计。

## 旧缓存一次性迁移

- 在战果档案中增加素战果追踪版本标记。
- 缺少当前追踪版本的旧档案在首次读取时：
  - 将当月所有每日记录的 `experience` 归零；
  - 清除累计经验基准，使下一次有效经验快照只建立新基准；
  - 保留每一日的 `eo` 与 `quest`；
  - 保留奖励状态、排名、目标值、计算用当前战果、身份、出击统计、收藏和隐藏。
- 迁移后的档案立即以新版本重新保存，后续启动不得重复归零。
- 新安装创建的空档案直接使用当前追踪版本，从 `0.00` 开始。

## 手动校正语义

设置页中的数值统一表示「本月累计素战果」，不是今日值。

### 素战果归零

- 在「存储与缓存」卡片增加「素战果归零」操作。
- 点击后显示二次确认，明确只清除本月素战果、不影响 EO、任务和其他战果数据。
- 确认后把当月所有每日记录的 `experience` 设为零，保留各日 `eo` 与 `quest`。
- 保留当前累计经验基准，后续真实经验增加继续从归零后的 `0.00` 累加，避免把既有累计经验再次计入。
- 成功后显示反馈提示。

### 手动填写素战果

- 在同一卡片增加「手动填写素战果」操作，并显示当前本月累计值。
- 点击后打开数字输入对话框，仅接受有限、非负数字，最多保留两位小数；空值、负数和非法值不得提交。
- 确认后先清除当月所有每日记录的 `experience`，再把输入值写入当前战果业务日的 `experience`；该日原有 `eo` 与 `quest` 必须保留。
- 保留当前累计经验基准，后续自动经验增量继续加在手动设定值上。
- 输入 `0` 与归零行为等价；成功后显示新的本月累计值。

## 组件与数据流

- `SenkaReducer` 负责累计经验的单调性保护及首次基准建立。
- `SenkaState` 负责追踪版本、兼容读取和只清理经验字段的迁移。
- `SenkaController` 提供本月素战果读取、归零和设置方法，沿用现有串行保存队列与通知机制。
- `SettingsPage` 将现有 `SenkaController` 传入 `DataSettingsPage`；控制器不可用时不显示两项素战果操作。
- `DataSettingsPage` 只负责确认、输入校验和用户反馈，不直接操作 SharedPreferences。
- 新增设置文案进入现有 `AppLocalizations`，保持项目现有简体中文、繁体中文和日文资源完整。

## 错误处理与边界

- 手动输入无法解析、非有限、负数或超过两位小数时保持对话框打开并显示错误，不写入缓存。
- 保存失败时控制器的串行队列仍可恢复，设置页显示失败反馈，不能显示成功提示。
- 每次归零或手动设置只触发一次状态替换和一次持久化。
- 手动操作不得清除累计经验基准；否则下一次 API 快照可能把已有累计经验重复计入。
- 旧缓存迁移是唯一会清除累计经验基准的路径，用于安全地重新建立可信基线。

## 测试与验收

- reducer 测试：首次快照只建基准、正增量正确换算、较小/相等/乱序快照不回退基准且不增加素战果、月份切换重新建基准。
- state/store 测试：旧版本档案只清除每日 `experience` 和经验基准，EO/任务及其余数据保留；新版本往返后不重复迁移。
- controller 测试：归零与手动设置覆盖多日记录，保留每日 EO/任务，后续经验增量继续累计，并验证单次保存。
- widget 测试：设置页仅在控制器可用时显示两个入口；归零确认/取消、手动输入校验、成功反馈和当前值显示均可交互。
- 回归运行战果专项测试、设置页测试、本地化契约、相关静态分析和 `git diff --check`。
- 保持 Debug 开发工作流，不构建或封装 release APK。

## 设置入口合并

- 「素战果归零」与「手动填写素战果」合并为一条「本月累计素战果」信息项，不再用分割线拆成上下两行。
- 副标题直接显示当前本月累计值，并随 `SenkaController` 更新。
- 信息项右侧依次放置两个独立、至少 44 dp 的图标按钮：铅笔按钮打开手动填写对话框，还原按钮打开归零确认对话框。
- 整条信息项本身不响应点击，避免用户误触；两个按钮分别提供 Tooltip、语义标签和稳定测试 key。
- 原有输入校验、二次确认、持久化及成功/失败反馈保持不变。

## 排名变化基准校准

- 归零或手动填写完成后，把当前玩家最新排名快照的 `localSenkaAtCapture` 同步为校正后的本月累计战果，使排名表“变化”从 `+0.00` 重新起算。
- 只替换 `rankingHistory['player']` 的最后一条快照中的本地基准；该快照的顺位、服务器战果和抓取时间保持不变。
- 更早的玩家快照、5/20/100/501 位固定排名快照以及全部排名历史均保持不变。
- 后续自动产生的素战果直接反映为新的正向变化，不把用户的校正操作显示成巨额负变化。
