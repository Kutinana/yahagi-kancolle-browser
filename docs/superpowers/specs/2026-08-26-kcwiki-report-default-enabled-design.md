# KCWiki 数据收集默认开启设计

## 目标

KCWiki 数据收集在用户尚未保存过开关选择时默认开启，提高新安装用户的数据贡献率。

## 行为边界

- 本地不存在 `kcwiki.report.enabled.v1` 时，将收集状态读为开启。
- 本地已保存 `true` 或 `false` 时，完整尊重用户的既有选择，不执行强制迁移。
- 用户仍可随时关闭收集，关闭立即生效并持久化。
- 用户在关闭后重新开启时，继续显示现有的数传输与隐私确认弹窗。
- 实际收集范围、脱敏、队列和传输机制保持不变。

## 界面文案

将现有各语言中“默认关闭”的描述改为“默认开启”，避免设置页说明与实际状态冲突。其他文案和布局不变。

## 实现方式

仅调整 KCWiki 设置存储层在键缺失时的回退值，并让内存测试存储使用相同默认语义。不更换偏好键，因此已有用户数据可直接沿用。

## 测试

- 验证缺少偏好时默认开启。
- 验证已保存的开启和关闭值均能恢复。
- 验证默认开启的设置页可立即关闭，且关闭会持久化。
- 验证从关闭状态重新开启时仍显示确认弹窗。
- 运行 KCWiki 设置和设置页相关测试，再运行全量测试。
