# 内置式岛风 Go 游戏资源缓存设计

## 目标

在 Yahagi 内部提供可预下载、可增量更新、可按需补漏的舰 C 静态资源缓存，降低每次启动后首次进入编成、补给等页面时的等待时间和重复流量。功能不依赖外部代理、证书或岛风 Go 缓存包，资源默认从舰 C 官方服务器获取。

## 产品定位

本功能采用“内置式岛风 Go 缓存”模式：核心行为与独立缓存代理一致，但缓存器直接接入 Android WebView 的请求拦截层，仅服务 Yahagi 内的游戏页面。

缓存模式控制预下载范围和运行时读写行为，不隐式删除已下载文件。清理缓存必须通过独立操作触发。

## 缓存模式

### 无本地缓存

- 作为默认模式。
- 完全旁路 Yahagi 自有资源缓存，不读取、不新增，也不启动预下载。
- 磁盘上已有资源继续保留，切回其他模式后可复用。

### 轻度缓存

- 用户选择后扫描目标清单，显示预计容量，确认后开始首次预下载。
- 目标包括客户端启动文件、常用 UI、当前已持有舰娘立绘和装备资源。
- 游戏实际访问到的其他允许缓存的静态资源也会自动写入缓存。
- 容量上限为 10 GiB，达到上限后按最近最少使用（Least Recently Used，LRU）策略淘汰。
- 正在使用、正在下载及轻度核心清单内的资源不作为优先淘汰对象。

### 完整缓存

- 用户选择后生成舰娘、装备、家具、地图、音效等全部当前已知资源清单。
- 下载前显示预计容量和设备可用空间，用户确认后一次性批量下载。
- 官方不提供单一资源包，因此“一次性下载”由 Yahagi 通过下载队列完成多个独立请求。
- 遗漏、后来新增或清单暂未识别的静态资源，在游戏实际访问时自动补入。
- 10 GiB 为硬上限。完整模式不执行 LRU；预计或实际达到上限时暂停并提示，不删除旧资源以伪造“完整”状态。
- “全部已知资源”仅包含当前客户端能够识别和访问的资源，不包含已下线、URL 未公开或无法推导的历史资源。

## 模式切换

- 无缓存切换到轻度：复用已有文件，仅补齐轻度清单。
- 无缓存切换到完整：复用已有文件，仅下载缺失或版本变化的资源。
- 轻度切换到完整：扩充目标清单，不重复下载。
- 完整切换到轻度：停止完整预下载，保留全部文件；后续新增资源时按轻度模式执行 LRU。
- 任意模式切换到无缓存：暂停批量任务并旁路缓存读写，保留文件、任务记录和下载进度。
- 切换模式本身永远不触发缓存清理。

## 资源来源与安全边界

- 静态资源从舰 C 官方资源服务器获取，并沿用 Yahagi 当前的系统网络、VPN 或代理设置。
- 现有第三方 Gadget 镜像只继续处理 Gadget 启动资源绕过，不作为完整缓存来源。
- 仅拦截允许列表内域名和路径的静态 `GET` 请求。
- 排除 DMM 登录、账号、支付、动态 HTML/PHP、`kcsapi` 和其他动态接口。
- 不保存 Cookie、请求正文、账号信息或游戏 API 响应。
- 限制重定向目标、单文件大小和总容量；响应 MIME 类型由受控扩展名规则与响应信息共同确定。

## 资源清单

资源清单由版本信息、`api_start2` 中的公开主数据、玩家持有舰娘和装备数据，以及 Yahagi 维护的静态资源路径规则共同生成。

- 轻度清单只包含启动、常用 UI 和当前玩家高频使用资源。
- 完整清单枚举当前可推导的所有已知静态资源。
- 清单生成失败不阻塞游戏；游戏请求仍可正常联网，并在启用缓存时执行按需补漏。
- 清单与实际访问共用同一缓存索引，避免预下载与运行时缓存重复落盘。

## 缓存键与版本更新

- 带 `version` 参数的资源以“规范化资源路径 + version”识别版本；游戏服务器主机变化不造成重复缓存。
- 路径和版本完全一致时直接返回本地文件，不发起网络下载。
- 路径相同但版本变化时下载新版本，校验成功后再切换当前版本。
- 不带版本参数的资源使用 `ETag`、`Last-Modified` 和缓存有效期进行条件请求。
- `version.json`、核心入口和关键主脚本每次游戏启动均联网校验，避免维护后使用过期客户端。
- 网络失败或响应异常时不覆盖现有有效文件；是否允许回退旧版本由资源类型决定，关键脚本不得静默回退不匹配版本。

## 请求与下载数据流

Android WebView 的请求拦截器负责运行时缓存：

1. 无缓存模式直接委托原 WebView 客户端。
2. 启用缓存时先检查允许列表和缓存索引。
3. 精确版本命中时从本地文件返回响应，并更新最后访问时间。
4. 未命中或版本变化时沿用当前网络设置访问官方服务器。
5. 网络响应同时提供给游戏并写入临时文件，不为缓存重复下载。
6. 文件完整写入并通过校验后，以原子操作替换正式文件并提交元数据。
7. 多个请求同时访问同一资源时合并为一个进行中的下载。

预下载器使用同一个网络获取器、校验器、文件存储和元数据索引。任务优先级从高到低为：游戏当前请求、启动及轻度核心资源、完整预下载资源。

## 自动更新策略

- 轻度或完整模式启用后，每次游戏成功启动执行轻量版本检查。
- Wi-Fi 下自动生成差异清单，并在后台补齐当前模式目标范围内的新增或变更资源。
- 移动网络下只显示预计下载量，用户确认后才执行批量更新。
- 游戏当前需要的遗漏或新资源始终正常加载，并在启用缓存时顺手写入，不受批量更新等待影响。
- Wi-Fi 断开时暂停后台批量任务；当前游戏资源继续使用现有网络加载。

## 持久化与异常恢复

- 正式资源存放在应用私有持久目录，不放入可能被 Android 主动回收的普通 `cacheDir`。
- 元数据记录规范化路径、版本、来源、类型、文件大小、校验信息、最后访问时间和完成状态。
- 下载先写入独立临时文件，校验成功后原子替换，避免应用退出或断网产生半文件。
- 下载队列支持暂停、继续、失败重试和应用重启后断点续传。
- 损坏检测只删除并重新获取对应文件，不自动清空整个缓存。

## 缓存完整性检查

“检查缓存完整性”操作执行以下步骤：

1. 获取当前游戏版本并重新生成轻度与完整目标清单。
2. 对比元数据和实际文件是否存在。
3. 校验版本、文件大小和已记录的完整性信息。
4. 对可疑文件及未正常结束的下载执行内容哈希校验。
5. 汇总缺失、过期、损坏及无法识别资源。

主界面只显示容量形式的完整度，例如：

```text
6.84 GB / 8.12 GB（84.2%）
```

底层仍按文件判断完整性。缺失文件数量、具体异常和预计补齐量只在详情页显示。即使当前为无缓存模式，也可以检查磁盘上保留文件对轻度、完整两套清单的覆盖率，但检查不会启用缓存读取。

检查结果提供“补齐并修复”操作，只有用户触发后才立即下载；正常的 Wi-Fi 自动增量更新仍按既定策略运行。

## 设置页交互

“存储与缓存”页面增加：

- 本地游戏缓存模式：无本地缓存、轻度缓存、完整缓存。
- 缓存完整度：单行显示“已缓存容量 / 目标容量（百分比）”。
- 当前状态：未启用、正在扫描、正在下载、已暂停、缓存完整、需要修复。
- 操作：开始或继续下载、暂停、检查缓存完整性、清空缓存。
- 下载状态：当前速度和预计剩余时间。

选择轻度或完整模式后，先扫描并显示预计容量，用户确认后才开始首次预下载。移动网络批量下载必须再次确认。点击完整度可进入详情页；清空缓存必须二次确认。

## 组件边界

- `GameResourceCachePolicy`：判断请求能否缓存、模式是否允许读写及资源优先级。
- `GameResourceCacheKey`：规范化主机、路径和版本，生成稳定缓存键。
- `GameResourceCacheStore`：负责文件原子写入、读取、删除和容量统计。
- `GameResourceCacheIndex`：持久化版本、完整性、访问时间和任务状态。
- `GameResourceFetcher`：沿用应用网络设置下载官方资源，处理条件请求和响应限制。
- `GameResourceRequestInterceptor`：接入 WebView，请求命中时返回本地响应，未命中时执行透传缓存。
- `GameResourceManifestBuilder`：生成轻度与完整资源清单。
- `GameResourceDownloadCoordinator`：负责优先级队列、并发合并、暂停、续传和网络约束。
- `GameResourceCacheController`：向 Flutter 设置页暴露模式、进度、完整度和维护操作。

各组件通过明确接口协作；请求拦截器不直接操作设置 UI，预下载器不维护第二套缓存。

## 验收标准

- 同版本静态资源第二次访问不产生网络下载。
- 游戏维护后只更新新增或版本变化的资源。
- 轻度与完整预下载均可暂停、恢复，并在应用重启后续传。
- 下载中断或校验失败不会覆盖有效缓存。
- 三种模式切换不删除文件；无缓存模式完全旁路自有缓存。
- Wi-Fi 自动补齐，移动网络批量下载必须确认。
- 轻度模式达到 10 GiB 时正确执行 LRU。
- 完整模式达到 10 GiB 时暂停并准确提示剩余需求。
- 完整度按“已缓存容量 / 目标容量（百分比）”显示。
- 完整性检查能发现缺失、过期和损坏资源，并能只修复异常部分。
- 登录、游戏 API、当前代理、Gadget 绕过、帧率补丁和游戏捕获管线保持正常。

## 测试策略

- 纯策略测试覆盖允许列表、缓存键、三档读写行为、版本变化和 LRU 选择。
- 存储测试覆盖临时文件、原子提交、损坏文件、容量边界和重启恢复。
- 下载协调测试覆盖优先级、请求合并、暂停续传、Wi-Fi 自动更新和移动网络确认。
- Android 集成测试覆盖 WebView 本地命中、网络透传、响应 MIME 类型和原客户端回退。
- Flutter 控制器与页面测试覆盖模式切换、容量显示、确认对话框、进度和错误状态。
- 回归测试证明动态 API、登录、代理、Gadget 绕过和主脚本补丁不进入普通资源缓存。

## 非目标

- 不导入或依赖岛风 Go、KCCacheProxy 等第三方缓存包。
- 不缓存历史上已下线且当前无法发现的资源。
- 不为其他浏览器或应用提供本地代理服务。
- 不缓存游戏动态 API 或用户敏感数据。
- 不承诺在 10 GiB 硬上限内容纳未来无限增长的完整资源集。
