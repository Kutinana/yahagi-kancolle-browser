# 新舰提醒与未持有一览设计

## 1. 目标

在「持有一览」中增加「持有 / 未持有」切换，并实现接近 POI「新舰力保」的提醒能力：

- 当前账号在获得舰娘前没有持有同一改造舰系时，将其视为「当前未持有的新舰」。
- 普通掉落、活动通关奖励、任务奖励和建造开箱均纳入检测范围。
- 战斗结算阶段只检测并暂存；进入母港后再显示提醒，避免遮挡结算和掉落演出。
- 新舰提醒同时包含游戏内醒目提示、Android 系统通知和震动。
- 用户可以按舰系排除不需要提醒的舰娘。
- 「未持有装备」仅用于查看收集情况，不产生提醒。

本设计不读取舰娘图鉴，也不判断账号历史上是否曾经拥有某艘舰娘。

## 2. 术语与判定规则

### 2.1 当前未持有舰系

每条舰娘改造链归并为一个舰系。获取目标舰娘前，只要账号仍持有该改造链中的任意形态，就不算当前未持有。

例如：

- 当前持有「夕立改二」，再次获得「夕立」时不提醒。
- 以前拥有「夕立」，但当前所有夕立系舰娘均已不存在，再次获得时提醒。
- 账号当前持有多个相同舰系实例时，继续获得同舰系舰娘不提醒。

舰系根节点根据 `api_mst_ship.api_aftershipid` 反向建立改造关系，不通过舰名后缀猜测。循环、缺失引用或异常主数据按目标舰娘自身的 Master ID 降级处理。

### 2.2 排除名单

排除名单保存舰系根节点 ID，而非具体改造形态 ID。勾选任意形态所属舰系后，该舰系的所有形态均不提醒。

排除设置不会因为获得、拆解或失去舰娘而自动删除。设置按 `api_member_id` 隔离，避免多个账号共用同一排除名单。

### 2.3 当前未持有装备

装备以 Master ID 独立计算，不合并改修或更新前后的派生装备。仓库和任意舰娘装备槽中的实例均计入持有数量；数量为 0 时显示在未持有装备页。

只展示主数据中 `api_sortno > 0`、名称非空且具备有效装备类型的玩家装备，排除敌方专用、内部占位和无图鉴排序记录。

## 3. 界面设计

### 3.1 顶部切换

「持有一览」标题右侧放置两组同规格胶囊按钮：

1. 左侧：「持有 / 未持有」。
2. 右侧：「舰娘 / 装备」。

形成 4 种页面组合：

| 持有状态 | 内容类型 | 页面行为 |
| --- | --- | --- |
| 持有 | 舰娘 | 保持现有舰娘表格不变 |
| 持有 | 装备 | 保持现有装备表格不变 |
| 未持有 | 舰娘 | 显示新舰提醒排除设置 |
| 未持有 | 装备 | 显示当前未持有装备 |

切换「持有 / 未持有」时保留最近选择的「舰娘 / 装备」页签。两组按钮在窄屏下仍保持同一行；空间不足时等宽压缩文字，不新增横向滚动。

### 3.2 未持有舰娘页

页面包含：

- 顶部说明：明确「仅显示当前未持有舰系」以及勾选代表「不提醒」。
- 统计：显示当前未持有舰系数量和已排除数量。
- 「清除排除」按钮：清空当前账号的全部舰系排除项，操作前显示确认对话框。
- 按舰种折叠的舰娘列表。

不提供搜索栏。

每张舰娘卡片显示：

- 横向头像。
- 第一行舰名。
- 第二行舰种。
- 右侧「不提醒」复选框。

舰名和舰种必须固定分为两行。长舰名只在第一行省略，不得挤压第二行。

列表只显示每个当前未持有舰系的基础代表舰。勾选后立即保存，卡片通过边框和背景变化反馈排除状态，不能只依赖颜色表达。

### 3.3 未持有装备页

页面顶部显示当前未持有装备种类总数，下方按装备类型折叠展示。

每张装备卡片只显示：

- 装备图标。
- 第一行装备名。
- 第二行装备类型。

不显示图鉴编号、火力、对空等属性，不提供搜索、复选框、排除设置或提醒说明。

## 4. 新舰事件检测

新增独立的 `GameApiEventConsumer` 负责获取事件识别和待提醒队列，不把提醒副作用写入 `GameStateReducer`。

消费者在接收事件时同步取得事件处理前的账号、主数据和持有舰系快照，再进入自己的顺序队列，避免与 `GameStateController` 的异步归并发生竞态。

### 4.1 战斗掉落与活动奖励

监听：

- `/kcsapi/api_req_sortie/battleresult`
- `/kcsapi/api_req_combined_battle/battleresult`

解析：

- 普通掉落：`api_get_ship.api_ship_id`。
- 活动奖励：`api_get_eventitem` 中 `api_type == 2` 的 `api_id`。

结算时完成舰系归一化、当前持有检查、排除检查和去重。符合条件的舰娘写入持久化待提醒队列，但不弹窗、不发送系统通知、不震动。

收到 `/kcsapi/api_port/port` 后发布队列中的战斗新舰提醒。多艘舰娘合并为一条提醒。

### 4.2 任务奖励

监听 `/kcsapi/api_req_quest/clearitemget`，解析 `api_bounus` 中 `api_type == 11` 的 `api_item.api_ship_id`。

任务领奖发生在母港，因此检测通过后立即发布，不等待下一次 `/api_port/port`。

### 4.3 建造开箱

监听 `/kcsapi/api_req_kousyou/getship`，从响应中的新增舰娘实例取得 Master ID。

建造开箱发生在母港，因此检测通过后立即发布，不等待下一次 `/api_port/port`。

### 4.4 去重

待提醒项目至少包含账号 ID、舰系根节点 ID、获取来源、API 事件序号和获取时间。相同 API 事件重复上报时不得产生多条提示；同一次事件获得多个符合条件的舰系时合并发布。

如果应用在战斗结算后、进入母港前退出，待提醒队列必须保留。下次捕获该账号的母港 API 后继续发布；不同账号的母港事件不能消费该队列。

## 5. 提醒呈现

### 5.1 游戏内提示

发布新舰提醒时显示不可通过点击遮罩关闭的对话框。内容包含：

- 标题：「获得当前未持有舰娘」。
- 舰娘名称；多艘时使用列表。
- 提示语：「记得为新舰上锁」。
- 明确的「知道了」按钮。

提示只提供信息，不自动操作游戏，也不尝试代替玩家锁船。

### 5.2 系统通知与震动

发布时向现有通知快照加入即时通知：

- 标题：「获得新舰」。
- 正文：「获得了 {舰名列表}，记得上锁。」
- 通知键由账号、事件序号和舰系集合构成，保证原生层幂等。

系统通知遵循现有通知总开关、提示音和震动设置。游戏内对话框不受系统通知权限影响；现有通知设置中的「震动提醒」开启时，对话框发布同时调用原生短震动。单次合并提醒只震动一次，不能按舰娘数量连续震动。

### 5.3 发布确认

系统通知交付失败时保留即时通知重试，但不重复显示已经出现的游戏内对话框或重复震动。待提醒队列在生成游戏内提醒状态后标记为已发布；用户点击「知道了」后移除对应游戏内提醒记录。

## 6. 状态与持久化

新增以下账号级本地状态：

- `excludedShipFamilyIds`：不提醒的舰系根节点 ID 集合。
- `pendingAcquisitions`：等待进入母港发布的战斗获取事件。
- `publishedAlertKeys`：短期幂等记录，用于防止桥接重放造成重复提示。

`publishedAlertKeys` 只需保留最近有限数量，按时间和数量双重裁剪。Master ID、舰系关系和未持有列表均从当前游戏主数据与玩家数据实时投影，不复制为长期静态目录。

## 7. 异常处理

- 主数据尚未加载：暂存原始 Master ID，主数据可用后再归一化；在此之前不误报。
- 玩家持有数据尚未加载：不判定新舰，等待权威母港数据后重新评估待处理事件。
- 未知舰名：使用「舰娘 ID {id}」作为降级文本，但仍按 Master ID 去重。
- 排除设置读取失败：使用空排除集合并在设置页显示非阻断错误，不丢弃原文件。
- 待提醒队列写入失败：仍允许本次内存提醒，但记录诊断错误；不得使游戏 API 管线失败。
- 系统通知权限关闭：保留游戏内对话框和按应用设置允许的前台震动。

## 8. 测试与验收

### 8.1 单元测试

- 改造链根节点计算，包括多段改造、缺失引用和循环降级。
- 当前持有舰系判定，包括持有改造形态、重复实例和完全失去后重新获得。
- 排除名单按舰系生效并按账号隔离。
- 普通掉落、活动奖励、任务奖励和建造开箱解析。
- 战斗事件只入队，母港事件才发布。
- 任务和建造事件在母港立即发布。
- 重放同一事件不会重复提示或重复震动。
- 多艘新舰合并为一次提醒和一次震动。
- 未持有装备过滤和持有数量计算。

### 8.2 Widget 测试

- 两组胶囊按钮可组合切换 4 个页面。
- 现有持有舰娘和持有装备页面行为不变。
- 未持有舰娘按舰种折叠，卡片固定两行，复选框可保存和恢复。
- 清除排除操作需要确认。
- 未持有装备不出现属性、图鉴编号、搜索和提醒控件。
- 长舰名、省略显示和窄屏布局不溢出。
- 新舰对话框不可点击遮罩关闭，点击「知道了」后关闭。

### 8.3 集成与真机验收

- 普通海域掉落新舰：结算阶段无提示，进入母港后出现对话框、系统通知和一次震动。
- 掉落当前已持有舰系：不提示。
- 掉落已排除舰系：不提示。
- 任务奖励和建造开箱：完成获取后在母港立即提示。
- 战斗结算后强制退出应用：重新进入同一账号母港后仍提示一次。
- Android 通知权限拒绝：游戏内提示仍可用。
- 通知震动关闭：不调用新舰前台震动；开启后每次合并提醒只震动一次。

## 9. 非目标

- 不读取或同步舰娘图鉴。
- 不判断账号历史首次获得。
- 不为未持有装备提供获取提醒。
- 不自动锁定舰娘，不拦截拆解、改修或强化操作。
- 不增加舰娘或装备搜索栏。
- 不复用 POI 图标或其他不在 MIT 授权范围内的视觉资产。
