# 游戏资源缓存基础清单调整设计

## 背景

现有完整缓存根据 `api_start2` 和路径规则枚举全部理论资源，目标数量和预计容量偏大，实际难以下载完成。用户提供了 `cache-2026-01-09` 基础缓存作为参考。该缓存包含 63,434 条索引记录，索引资源总长度约 5.74 GB，磁盘文件总量约 5.77 GB。

本次调整保留无本地缓存、轻量缓存和完整缓存 3 种模式，但重新定义完整缓存的目标范围，使其成为一个固定、可预估且能实际完成的基础清单。

## 目标

- 保持类似岛风 Go 的本地资源缓存体验：本地优先、缺失回源、访问后自动写入。
- 轻量缓存继续使用账号相关的动态精简清单。
- 完整缓存改用 63,434 条基础缓存索引作为固定目标，预计约 5.8 GB。
- 所有资源仍从舰队 Collection 官方服务器获取，不分发第三方缓存文件。
- 将本地缓存容量上限调整为十进制 50 GB，并统一采用 LRU 淘汰。
- 模式切换、游戏更新和应用退出不得造成缓存冲突、主线程卡顿或已有文件丢失。

## 已验证的输入

基础索引位于：

```text
G:\迅雷下载\cache-2026-01-09\cache\cached.json
```

验证结果如下：

- 索引记录：63,434 条。
- 原始索引大小：10,285,177 字节。
- Gzip 压缩后大小：797,956 字节，约 0.76 MB。
- 所有路径均位于 `/gadget_html5`、`/html`、`/kcs`、`/kcs2` 或 `/kcscontents` 目录。
- 索引包含相对路径、版本参数、`Last-Modified`、文件长度和缓存策略等元数据。
- 按目录分层抽样并验证 29 个官方 URL，全部返回 HTTP 200。

抽样结果证明路径可以映射到官方资源服务器，但不承诺每一条历史资源永久在线。个别失效资源应按普通下载失败处理。

## 缓存模式

### 无本地缓存

- 不读取、不新增 Yahagi 游戏资源缓存。
- 不启动批量预下载。
- 已有文件继续保留，切换回其他模式后可以复用。

### 轻量缓存

- 清单由客户端启动文件、常用 UI、当前已持有舰娘和装备资源组成。
- 根据当前账号数据和 `api_start2` 动态生成。
- 用户确认后才开始批量下载。
- 游戏实际访问到的其他静态资源也自动写入本地缓存。

### 完整缓存

- 使用内置的基础清单，不再枚举全部理论资源。
- 基础清单由 `cached.json` 转换而来，保留相对路径、版本和预期长度。
- 预计目标容量约 5.8 GB，界面使用索引真实长度计算总量。
- 用户确认后才开始批量下载，可暂停、继续和重启续传。
- 基础清单外的新资源在游戏访问时自动写入缓存。
- 后续应用版本可以更新内置基础清单，但不因此删除已有资源。

## 清单生成与打包

新增构建期转换脚本，将第三方索引转换为 Yahagi 自有的只读基础清单：

1. 读取 `cached.json`。
2. 校验路径前缀、版本格式和非负文件长度。
3. 删除重复项并保持稳定排序。
4. 只保留预下载所需字段：相对路径、版本参数、预期长度。
5. 输出压缩资源文件及摘要信息，包括条目数、总长度和内容哈希。

应用只包含清单，不包含 PNG、MP3、JavaScript 或其他第三方缓存资源。转换脚本不在运行时读取用户电脑上的下载目录。

## 官方 URL 映射

- `/kcs` 和 `/kcs2` 使用当前游戏资源服务器域名。
- `/gadget_html5`、`/html` 和 `/kcscontents` 使用官方 Gadget 资源域名。
- 保留索引中的版本查询参数。
- 仅允许 HTTPS、静态 GET 请求及现有缓存规则认可的文件类型。
- 不缓存登录、支付、`kcsapi` 或其他动态接口。

如果当前服务器或官方入口发生变化，运行时使用最新已知官方域名重新组合 URL，不把旧服务器主机写死为缓存键的一部分。

## 运行时数据流

1. WebView 请求静态资源时先查询本地缓存。
2. 版本一致且文件有效时直接返回本地内容，并更新最后访问时间。
3. 缺失、损坏或版本变化时请求官方服务器。
4. 官方响应同时提供给游戏，并在校验成功后原子写入缓存。
5. 轻量或完整预下载与游戏请求共用同一个缓存存储和索引。
6. 游戏当前请求优先于后台预下载任务。

个别基础清单资源返回 404、超时或校验失败时，只记录对应项目失败。下载队列继续处理其他资源，游戏请求也继续正常回源。

## 游戏更新与冲突处理

- 带版本参数的资源以规范路径和版本识别。
- 路径相同但版本变化时，下载并校验新版本后原子替换当前版本。
- 不带版本参数的资源使用 `ETag`、`Last-Modified` 和有效期执行条件校验。
- 网络失败或响应不完整时保留旧的有效文件。
- 新资源在实际游玩时自动进入本地缓存，不要求等待下一版基础清单。
- 后续内置清单更新只扩充或修正目标，不主动清空缓存。

## 容量与 LRU

- 本地游戏资源缓存硬上限为十进制 50,000,000,000 字节。
- 轻量缓存和完整缓存都使用 LRU 淘汰。
- 写入前先为新文件预留空间，优先淘汰最久未访问且未被当前请求或下载任务占用的资源。
- 当前目标清单资源可以被淘汰，但完整性状态随之变为缺失；玩家可通过继续下载或修复重新获取。
- 容量显示与目标完整度分开：容量上限不作为下载目标分母。

## 设置页交互

- 保留无本地缓存、轻量缓存和完整缓存 3 个选项。
- 轻量缓存说明强调账号相关的精简范围。
- 完整缓存说明明确写为「约 5.8 GB 的固定基础资源清单」。
- 显示「已缓存目标容量 / 当前模式目标容量（百分比）」。
- 提供开始下载、暂停、继续下载、检查完整性、补齐或修复、清除缓存操作。
- 移动网络批量下载必须二次确认；Wi-Fi 中断后自动暂停并在恢复后继续。
- 容量不足时提示 50 GB 上限，不再使用旧的 10 GB 文案。

## 完整性语义

- 轻量模式检查当前动态轻量清单。
- 完整模式检查内置的 63,434 条基础清单。
- 「完整」表示当前模式目标清单完整，不表示拥有所有历史或未来理论资源。
- 检查结果统计缺失、损坏和过期项目，并使用索引真实长度计算容量进度。

## 持久化与升级

- 清单快照与高频下载进度分开保存。
- 清单更新使用临时文件和原子替换，并保留上一份备份。
- 模式切换使旧任务失效，但不删除缓存文件。
- 已经使用旧完整枚举清单的安装，在收到新内置基础清单后替换下载目标；已有资源继续复用。
- 应用退出只执行无阻塞失效，不在主线程等待大清单扫描或落盘。

## 测试策略

- 转换脚本测试：条目数、路径允许列表、去重、稳定排序、总长度和摘要。
- 清单加载测试：压缩资源解码、版本拼接、官方域名映射和损坏清单拒绝。
- 轻量清单测试：只包含当前账号相关资源。
- 完整清单测试：使用固定基础索引，不再调用理论全量枚举。
- 缓存引擎测试：本地命中、版本更新、条件校验、失败保留旧文件和 50 GB LRU。
- 下载协调测试：暂停续传、应用重启、网络切换、个别 404 继续队列和模式竞态。
- Flutter 测试：三种模式、约 5.8 GB 说明、容量进度、确认对话框和 50 GB 提示。

## 验收标准

- 同版本资源第二次访问直接命中本地缓存。
- 轻量模式仍生成账号相关精简清单。
- 完整模式目标固定为转换后的 63,434 条基础索引，目标容量使用真实长度。
- 完整资源全部从官方服务器获取，APK 不包含第三方资源文件。
- 单项下载失败不终止整个队列，也不影响正常游戏。
- 游戏更新后新资源能够边玩边写入，旧有效文件不会被失败响应覆盖。
- 3 种模式切换不删除已有缓存，旧下载任务不能覆盖新模式。
- 50 GB LRU 上限按十进制显示和执行。
- 大清单生成、解析、传输、校验和持久化不阻塞 Flutter 或 Android 主线程。

## 非目标

- 不直接导入或分发 `cache-2026-01-09` 中的资源文件。
- 不承诺基础清单覆盖所有历史、下线或未来资源。
- 不提供给其他应用使用的本地代理服务。
- 不缓存游戏动态 API、账号凭据、Cookie 或支付数据。
