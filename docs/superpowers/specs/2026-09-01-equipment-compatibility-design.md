# 装备可装备舰娘查询设计

## 背景与目标

玩家在仓库查看一件装备时，需要知道哪些舰娘形态可以在普通装备槽或增设装备栏中使用该装备。

本功能以游戏 `api_start2/getData` 返回的官方主数据为唯一规则来源，不维护人工舰娘名单。结果按具体改造形态展示，例如「矢矧」「矢矧改」「矢矧改二乙」分别计算。

## 用户体验

### 入口

入口位于「仓库 → 持有 → 装备」表格。

- 点击装备行后，从页面右侧滑出详情抽屉。
- 抽屉打开时点击另一件装备，直接替换详情内容，不先关闭抽屉。
- 点击关闭按钮后收起抽屉，并取消装备行的选中状态。
- 舰队信息中心的装备详情暂不接入，本次只实现仓库入口。

### 抽屉布局

宽屏下抽屉宽度约为 438 px，包含以下区域：

1. 装备图标、名称、分类、官方 ID。
2. 当前持有数量、普通槽可装备形态数、增设栏可装备形态数。
3. 「持有舰娘」与「全部舰娘」切换。
4. 舰娘名称搜索框。
5. 「全部」「普通槽」「增设栏」结果筛选。
6. 按舰种分组的舰娘列表。
7. 官方主数据来源提示。

窄屏下抽屉从右侧进入并占据接近全宽的空间，内容结构保持一致。

### 舰娘结果

每个结果展示：

- 舰娘头像与具体改造形态名称；
- 「持有舰娘」模式下展示等级和编成状态；
- 舰种与舰级；
- 「普通槽」「增设栏」或「普通槽＋增设栏」标签；
- 增设栏存在改修要求时展示最低改修等级，例如「增设栏需 ★+4」。

「全部舰娘」只包含可用的玩家舰娘主数据，不包含深海舰船。筛选规则沿用项目现有约定，排除 ID 大于 1500 的主数据。

## 数据模型

### 普通装备槽规则

当前 `MasterShip.equipTypeIds` 只保存可装备类别，无法表达 `api_mst_equip_ship.api_equip_type` 中的具体装备白名单。新增完整规则模型，至少保存：

- 舰娘主数据 ID；
- 可装备类别 ID 集合；
- 按类别划分的具体装备 ID 白名单。

若某类别的值是数组，则该舰娘只能装备数组列出的具体装备；不能把整个类别判定为可装备。

### 增设装备栏规则

从 `api_start2/getData` 解析并持久化：

- `api_mst_equip_exslot`：通用增设栏装备类别；
- `api_mst_equip_exslot_ship`：按装备 ID 定义的舰娘 ID、舰级、舰种和最低改修等级规则；
- `api_mst_equip_limit_exslot`：指定舰娘禁止在增设栏使用的装备类别。

特殊规则中的舰种 ID `99` 表示全部舰种。

### 查询结果

建立独立的装备适配查询服务。输入舰娘主数据 ID 与装备主数据 ID，返回：

- `canEquipInRegularSlot`；
- `canEquipInExpansionSlot`；
- `expansionSlotMinimumImprovement`。

UI 不直接解释原始 API 结构，只消费查询服务的稳定结果。

## 判定规则

### 普通槽

1. 读取装备的实际类别 ID。
2. 读取舰种通用可装备类别与舰娘专属覆盖规则。
3. 若该类别存在具体装备白名单，只在装备 ID 命中白名单时允许。
4. 输出普通槽是否可装备。

项目已有少量装备实际类别与 `api_type[2]` 不同的情况。查询服务应复用或补充项目的装备类别修正规则，避免仅依赖原始 `api_type[2]`。

### 增设栏

1. 装备类别位于 `api_mst_equip_exslot`，且舰娘具备相应普通槽类别能力时，初步允许。
2. 若舰娘命中 `api_mst_equip_limit_exslot`，移除对应通用增设栏能力。
3. 若装备命中 `api_mst_equip_exslot_ship`，再按舰娘 ID、舰级或舰种匹配特殊能力。
4. 特殊规则包含 `api_req_level` 时，保留最低改修等级并交给 UI 展示。
5. 普通槽与增设栏分别输出，不因其中一项成立而推断另一项成立。

## 数据流与缓存

```text
api_start2/getData
  → GameStateReducer 解析完整装备规则
  → GameState 与序列化缓存保存主数据
  → EquipmentCompatibilityService 执行单舰娘判定
  → EquipmentCompatibilityProjection 生成全部/持有列表
  → 右侧详情抽屉展示
```

适配结果按装备主数据 ID 缓存。主数据对象变化时清空缓存；玩家持有舰娘、等级或编成变化时只重建「持有舰娘」投影，不重新解析官方规则。

## 状态与异常处理

- 尚未取得主数据：抽屉显示「装备规则数据等待更新」，不展示猜测结果。
- 所选装备在主数据中不存在：显示「未知装备」，并提供官方 ID。
- 规则字段缺失或结构异常：安全降级为不可判定，同时记录诊断日志；不能把未知规则显示为「不可装备」。
- 没有匹配结果：分别显示「当前没有持有可装备的舰娘」或「没有找到可装备的舰娘形态」。
- 设备旋转或窗口宽度变化：保持当前选中装备、标签页、搜索词和筛选项。
- 游戏状态刷新后装备被删除：关闭抽屉并清除选择。

## 可访问性与交互

- 装备行提供按钮语义和选中状态。
- 抽屉打开后，键盘焦点进入抽屉标题；关闭后返回原装备行。
- `Esc` 关闭抽屉。
- 标签颜色不能作为唯一信息来源，必须同时显示文字。
- 抽屉与列表滚动互不干扰。

## 测试方案

### 解析与序列化测试

- 解析通用舰种装备类别。
- 解析舰娘专属类别覆盖。
- 保留具体装备 ID 白名单。
- 解析通用增设栏类别。
- 解析按舰娘 ID、舰级、舰种和舰种 `99` 的特殊增设栏规则。
- 解析并持久化最低改修等级与增设栏限制。
- 序列化后重新加载，规则内容保持一致。

### 判定服务测试

- 仅普通槽可装备。
- 仅增设栏可装备。
- 普通槽与增设栏均可装备。
- 具体装备白名单命中和未命中。
- 通用增设栏类别被单舰娘限制排除。
- 特殊舰娘、舰级、舰种规则分别命中。
- 最低改修等级正确返回。
- 未知舰娘、未知装备和主数据缺失时返回未知状态。

测试数据优先采用项目内固定 fixture，至少选择一组当前官方 `start2` 数据中的真实规则作为回归样例。

### 投影与组件测试

- 「持有舰娘」只显示玩家当前拥有的具体形态，并展示等级和编成状态。
- 「全部舰娘」包含未持有形态并排除深海舰船。
- 按舰种分组、名称搜索及槽位筛选正确。
- 点击装备行打开抽屉，切换装备时内容原地替换。
- 关闭抽屉后清除选中状态。
- 窄屏布局不溢出，抽屉接近全宽。
- 主数据等待、未知规则和空结果状态正确。

## 验收标准

- 用户能从仓库装备列表点击任意已持有装备，查看可装备的全部舰娘形态和当前持有舰娘。
- 普通槽与增设栏能力清晰区分。
- 需要最低改修等级的增设栏规则不会被显示为无条件可装备。
- 官方主数据中的具体装备白名单和单舰娘限制不会被类别级判断覆盖。
- 相关自动化测试通过。
- 在 `master` 分支构建 Debug APK 成功，并提供 APK 路径供安装验证。

## 非目标

- 本次不实现从抽屉直接换装。
- 本次不接入舰队信息中心的装备详情入口。
- 本次不依赖舰娘百科或其他在线 API。
- 本次不维护人工装备兼容名单。
