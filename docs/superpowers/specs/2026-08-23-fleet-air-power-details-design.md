# 舰队制空详情设计

## 背景

首页「编队简报」和舰队中心目前默认显示舰队制空下限。当同一熟练度等级对应的内部熟练度存在区间时，界面以 `下限+` 提示制空值还有上浮空间，但用户无法直接查看制空上限和不计熟练度加成时的结果。

本功能为两处制空指标增加统一详情弹窗。交互和视觉样式沿用现有「索敌详情」。

## 目标

- 首页和舰队中心的制空指标均可点击。
- 两处打开同一个「制空详情」弹窗。
- 弹窗展示最小、最大、无加成 3 个值。
- 默认胶囊仍显示制空最小值；存在区间时继续显示 `最小值+`。
- 计算口径与 POI 一致：无加成仅移除熟练度相关贡献，保留装备改修补正。

## 非目标

- 不改变制空胶囊默认显示值。
- 不增加制空显示模式切换或持久化设置。
- 不展示逐舰娘、逐装备或逐格制空明细。
- 不调整索敌公式和索敌详情内容。

## 计算规则

`FleetMetrics` 为每个有效舰载机格计算并汇总 3 种制空值：

1. **最小：** 使用当前显示熟练度对应的内部经验下界，包含熟练度固定奖励、内部熟练度奖励及改修补正。
2. **最大：** 使用当前显示熟练度对应的内部经验上界，包含熟练度固定奖励、内部熟练度奖励及改修补正。
3. **无加成：** 不计熟练度固定奖励和内部熟练度奖励，但保留装备改修补正。

单格无加成制空按以下顺序计算并向下取整：

```text
effectiveAntiAir = equipmentAntiAir + improvementLevel * improvementFactor
slotAirPowerWithoutProficiency = floor(sqrt(planeCount) * effectiveAntiAir)
```

舰队结果为所有有效舰载机格结果之和。装备或装备主数据缺失时，3 个值均视为未知，避免用不完整数据误导用户。

## 交互与界面

### 默认指标

- 首页继续显示现有 `制空` 胶囊。
- 舰队中心继续显示现有 `制空` 指标格。
- 最小值与最大值不同时显示 `最小值+`；相同时显示单个数值。
- 数据完整时整个指标格可点击；数据未知时不响应点击。

### 详情弹窗

弹窗样式与「索敌详情」一致：深色背景、标题、左右两列详情行、分隔线和底部关闭按钮。

内容顺序固定为：

| 标签 | 值 |
| --- | --- |
| 最小 | 舰队制空最小值 |
| 最大 | 舰队制空最大值 |
| 无加成 | 不计熟练度加成的舰队制空值 |

弹窗标题为「制空详情」。点击首页或舰队中心的制空指标，展示结果完全一致。

## 架构

### 数据模型

在 `FleetMetrics` 中增加可空字段 `airPowerWithoutProficiency`。现有 `airPower` 和 `airPowerMaximum` 分别继续表示最小值和最大值。

内部单格计算结果由 2 项扩展为 3 项：

```dart
({int minimum, int maximum, int withoutProficiency})
```

### 共享弹窗

新增 `fleet_air_power_details.dart`，提供：

```dart
Future<void> showFleetAirPowerDetails(
  BuildContext context,
  FleetMetrics metrics,
)
```

该文件只负责展示制空详情。首页和舰队中心均调用这一入口，不重复实现弹窗。

索敌详情保持独立，避免为了少量相似布局引入通用弹窗抽象。

## 本地化与无障碍

简体中文、繁体中文和日文资源新增：

- 制空详情；
- 最小；
- 最大；
- 无加成；
- 点击查看制空详情的语义说明。

制空指标在可点击时提供按钮语义；数据未知时不宣告可点击动作。

## 测试

### 计算测试

- 熟练度和改修同时存在时，最小值、最大值、无加成值符合公式。
- 无加成值保留改修补正。
- 多个舰载机格按逐格取整后求和。
- 装备数据缺失时 3 个制空值均为空。

### 界面测试

- 首页点击制空胶囊可打开详情。
- 舰队中心点击制空指标可打开详情。
- 两处弹窗均按最小、最大、无加成顺序显示相同数值。
- 数据未知时不打开弹窗。
- 现有默认制空显示和索敌详情不回归。

## 验收标准

- 两处制空指标均可点击，并打开统一的制空详情弹窗。
- 弹窗展示最小、最大、无加成 3 项。
- 无加成的计算保留改修补正，只去掉熟练度贡献。
- 默认胶囊显示保持现状。
- 相关定向测试、静态分析和全量测试通过。
