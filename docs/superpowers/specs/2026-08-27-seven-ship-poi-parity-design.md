# 游击部队七舰战斗预测 POI 一致性设计

## 背景

Yahagi 的普通六舰战斗预测目前表现正常，但游击部队七舰编成中出现友军 HP 预测错误。现有诊断文件没有保存该场战斗的完整原始 API body，因此无法还原截图中每一阶段的具体伤害；代码对比已经确认 Yahagi 在部分炮击索引判断中使用固定边界 `6`，而 POI 使用本场主舰队的实际长度。

本次修改只处理七舰游击部队兼容，不重构目前正常工作的战斗包收集与重放架构。

## 目标

- 炮击数据缺少 `api_at_eflag` 时，按照 POI 使用实际主舰队长度判断攻击方并换算目标位置。
- 预测引擎与备用伤害解析器采用相同的动态边界规则。
- 战斗会话能够保存完整的七舰快照，便于诊断和回归。
- 六舰通常舰队和联合舰队行为保持不变。
- 不使用战果 S/SS 将预测沉船强制改写为 `1 HP`。

## 非目标

- 不重写战斗事件采集或包重放架构。
- 不改变伤害控制道具的结算规则。
- 不全面替换所有常量 `6`。属于舰队 API 固定槽位和联合舰队位置编码的常量仍保留。
- 不把官方战果页当作精确剩余 HP 来源。

## 设计

### 动态炮击边界

在缺少 `api_at_eflag` 的炮击数据中，行为与 POI `lib-battle` 保持一致：

- `mainFleetRange = friendMain.length`
- 防守方位置小于 `mainFleetRange` 时，判定为敌方攻击。
- 需要从合并位置转换为单舰队位置时，减去 `mainFleetRange`，而不是固定减 `6`。

该规则同时应用于普通攻击和多目标攻击。已有 `api_at_eflag` 时继续优先使用服务端明确标志。

### 解析器一致性

`PoiBattlePredictionEngine` 和 `BattleDamageParser` 都包含炮击解析逻辑。两处必须使用同一语义：实际友方主舰队长度决定缺省攻击方分界。这样实时预测和备用解析不会对同一个七舰包产生不同结果。

联合舰队明确使用 API 固定槽位的路径不做无依据修改。敌方主力/随伴舰映射继续依据各自已捕获舰队结构处理。

### 七舰会话记录

`BattleSession` 不再把主舰队快照截断为六个位置。会话记录至少容纳七艘游击部队舰船，并保持现有空位和位置编号语义，使后续诊断文件能包含第七舰。

### 战果校验

移除 S/SS 后把预测 HP 从零改为一的修正。战果只能证明没有友舰沉没，无法证明其剩余 HP 为一。预测数据继续来自战斗模拟；发生矛盾时保留不一致信息，而不伪造数值。

## 测试策略

采用测试驱动方式，先确认新增用例在旧实现上失败，再修改生产代码：

1. 七舰且缺少 `api_at_eflag` 时，使用边界七判断攻击方。
2. 七舰的合并目标位置按七换算，编号六和七附近不会错位。
3. 第一舰不会接收属于其他位置的伤害，第七舰能够正确接收属于自己的伤害。
4. `BattleDamageParser` 与 POI 预测引擎对同一七舰输入得出相同 HP。
5. `BattleSession` 完整保存七艘舰船。
6. 官方 S/SS 结果不再把预测 HP 伪造为一。
7. 运行战斗相关完整测试、静态分析和现有 POI 战例语料对照。

## 成功标准

- 新增七舰回归测试全部通过，并在修复前能稳定复现失败。
- 原有六舰、联合舰队和 POI 语料对照测试无回归。
- 静态分析无新增问题。
- 修改范围限于七舰索引、七舰会话记录和移除临时 HP 修正。
