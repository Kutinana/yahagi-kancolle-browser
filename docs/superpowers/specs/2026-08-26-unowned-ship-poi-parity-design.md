# 未持有舰娘 POI 口径与界面精简设计

## 目标

让未持有舰娘的数量与 POI `poi-plugin-lock-reminder` 使用相同的改造家族口径，同时精简未持有舰娘界面中的重复统计和舰种折叠层级。

## 数量口径

- 仅处理玩家舰主数据，舰娘 Master ID 必须不大于 1500。
- 按 POI 的 `shipRemodelInfoSelector` 规则构建改造家族：
  1. 收集所有改造后继 ID。
  2. 没有其他舰娘指向的形态作为家族初始舰。
  3. 从初始舰沿 `afterShipId` 向后遍历；遇到循环时停止，但已访问形态仍属于该初始舰。
  4. 对未被任何初始链覆盖的异常形态，按 Master ID 升序选择新的根并重复遍历。
- 账号当前持有家族任意形态时，该家族不属于“未持有”。
- 未持有列表使用家族初始舰作为代表，与 POI 的展示和排除 ID 保持一致。

## 已确认根因

旧实现通过“后继到前驱”的映射反向查根。对于可逆转换形成的循环，前驱取决于主数据遍历顺序；循环检测后又把当前形态自身当根，因此会把同一家族拆成多个家族。

使用 POI 测试主数据对照：POI 得到 322 个家族，旧实现得到 328 个家族。差异来自 6 个被错误拆出的循环形态：Fletcher 改 Mod.2、Fletcher Mk.II、宗谷的两个转换形态、Glorious 改的两个转换形态。

## 顶部统计

- 删除舰娘列表中的独立摘要行“显示 X 艘 · 已排除 Y 艘”。
- 在现有顶部筛选条的“筛选结果 X”后追加“· 已排除 Y”。
- 结果数和已排除数都使用现有黄色强调色。
- `Y` 是当前舰种筛选结果与排除集合的交集数量，不显示其他舰种或已不在未持有列表中的旧排除项。
- 存在排除项时，将“清空排除”操作放在顶部统计末尾。
- 装备筛选条不增加排除统计。

## 列表布局

- 删除“驱逐舰（X）”等 `ExpansionTile` 舰种分组标题。
- 未持有舰娘卡片直接放入一个可滚动的 `Wrap` 平铺布局。
- 卡片继续显示头像、名称、舰种和排除勾选，不改变排除交互。
- 未持有装备页保持现有分组布局。

## 测试

- 投影测试覆盖带入口的改造循环，验证循环内形态只产生一个家族，并与 POI 根一致。
- 投影测试覆盖 Master ID 大于 1500 的非玩家舰不参与统计。
- 页面测试验证独立摘要和舰种折叠标题消失。
- 页面测试验证顶部筛选结果后显示黄色的当前筛选排除数。
- 运行相关测试、定向静态分析和完整 Flutter 测试套件。
