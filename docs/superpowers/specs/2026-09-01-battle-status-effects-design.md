# 战斗状态效果细分设计

日期：2026-09-01

## 目标

把分散在「画面与声音」和「战斗」中的动态状态效果集中到「设置 → 战斗」，让用户分别控制受损闪烁、受损震动和士气星光，并能限制画面效果出现于未卜先知、编队或两者。

本次不改变「大破进击保护」的独立设置和安全弹窗行为，也不改变疲劳脸、Cond 数值、出击疲劳警告及 Cond 49 恢复通知。

## 已确认的界面

「设置 → 战斗」保留现有「大破提醒」卡片。其下新增「战斗状态效果」卡片，顺序如下：

1. 「启用状态效果」总开关；
2. 「画面显示范围」：仅未卜先知／仅编队／全部；
3. 「受损闪烁」：关闭／仅小破／仅中破／仅大破／全部开启；
4. 「受损震动」：关闭／仅中破／仅大破／全部开启；
5. 「士气闪光效果」：开启／关闭。

总开关关闭时，下面四项变成不可操作的弱化状态，但保留各自已选值；重新开启后恢复原选择。

页面沿用现有设置 UI：`#0d1a26` 页面背景、`#142735` 卡片、12 px 圆角、金色分区标题、现有字号和间距。已确认的交互 Demo 位于：

`.superpowers/brainstorm/damage-alert-settings-demo-20260901/battle-status-effects-demo.html`

## 设置模型

新增一个由战斗安全设置控制器持有的状态效果配置，包含：

- `enabled`：总开关，默认 `true`；
- `displayScope`：`predictionOnly`、`fleetOnly`、`all`，默认 `all`；
- `damagePulseFilter`：`off`、`minorOnly`、`moderateOnly`、`heavyOnly`、`all`，默认 `all`；
- `damageVibrationFilter`：`off`、`moderateOnly`、`heavyOnly`、`all`，默认 `all`；
- `moraleSparkleEnabled`：默认 `true`。

持久化使用稳定字符串枚举；遇到未知值时回退默认值，不能因损坏的偏好设置导致页面无法启动。

总开关只影响有效行为，不覆盖或重写子项。画面显示范围只控制受损闪烁和士气星光，不控制震动；震动没有页面显示归属。

## 损伤等级

所有画面和震动规则共用同一损伤等级函数，避免边界不一致：

- 健全：`currentHp * 4 > maxHp * 3`；
- 小破：`maxHp * 2 < currentHp * 4 <= maxHp * 3`，即 `50% < HP ≤ 75%`；
- 中破：`maxHp < currentHp * 4 <= maxHp * 2`，即 `25% < HP ≤ 50%`；
- 大破：`0 < currentHp * 4 <= maxHp`，即 `0 < HP ≤ 25%`；
- HP 为 0 或最大 HP 无效时不属于可提醒等级。

「仅某等级」是严格匹配，不是阈值包含。例如选择「仅中破」时，中破闪烁，大破不闪烁。

无论动态闪烁是否开启，现有 HP 条、HP 数字、边框的红／橙／黄／绿／灰静态颜色保持不变。

## 画面显示范围

### 未卜先知

包括首页未卜先知卡片及详细战斗面板。受损闪烁保持现状，对己方和敌方舰船均生效。

### 编队

包括首页编队简报、舰队中心舰娘卡片及陆基航空队状态卡。陆基航空队归入非预测的编队侧状态画面。

士气星光只存在于能取得 Cond 的己方舰娘头像；未卜先知没有 Cond 数据时不制造推测值，也不显示士气星光。因此选择「仅未卜先知」时，士气星光设置保留，但当前没有可显示目标。

### 全部

同时启用上述两类画面。

## 受损闪烁

现有普通／强化两种动画模式收敛为现有强化动画样式，新增等级过滤：

- `off`：所有损伤等级均没有动态动画；
- `minorOnly`：仅小破使用黄色慢速强化呼吸；
- `moderateOnly`：仅中破使用橙色强化呼吸；
- `heavyOnly`：仅大破使用红色快速强化呼吸；
- `all`：小破、中破、大破分别使用现有强化动画。

过滤发生在统一视觉策略层，`ShipHpFrame` 与 `DamagePulseBuilder` 使用同一个有效策略，不能由各页面自行重复判断。

## 受损震动

震动只针对我方舰娘，保留现有以下前置条件：

- 排除演习；
- 排除退避舰；
- 排除 HP 未下降的更新；
- 战斗预测账本不可信时不触发；
- 仅在本次攻击结算后进入新的、更严重损伤等级时触发。

震动按结算后的最终等级判断。健全直接掉到大破时视为大破，不视为途经中破。模式行为：

- `off`：不震动；
- `moderateOnly`：仅最终新进入中破时震动；
- `heavyOnly`：仅最终新进入大破时震动；
- `all`：新进入中破或大破时震动。

同一阶段多舰受损时，先过滤未启用等级，再从剩余事件选择最严重等级；每阶段最多震动一次。中破沿用一次约 300 ms， 大破沿用 255 ms、停 90 ms、再 255 ms。

战后选择进击时的大破安全弹窗继续只由「大破进击保护」控制，不能被状态效果总开关或震动筛选关闭。弹窗伴随的震动视为大破震动：只有状态效果总开关开启且震动筛选包含大破时才触发。这样选择「仅中破」或关闭震动时仍会显示关键安全弹窗，但不会产生大破警告震动。

## 士气闪光效果

该开关只控制 Cond ≥ 50 时舰娘头像周围的星光动画。关闭后仍保留：

- Cond 数值及颜色；
- Cond < 30 的黄／红疲劳脸；
- 出击准备简报中的疲劳警告；
- Cond 49 恢复倒计时及 Android 系统通知；
- 野崎刷闪相关计时与通知。

士气星光策略应作为 `ShipMoraleMark` 的显式输入，不能通过伪造 Cond 或停用整个士气标记实现。

## 旧设置迁移

新设置键不存在时执行一次兼容读取：

- 旧 `battle.damageVibrationEnabled == true` → `damageVibrationFilter = all`；
- 旧 `battle.damageVibrationEnabled == false` → `damageVibrationFilter = off`；
- 旧 `layout_enhanced_damage_pulse` 无论为 `true`、`false` 或不存在 → `damagePulseFilter = all`，因为旧版两种模式实际都会让小破、中破和大破闪烁；
- `displayScope = all`；
- `enabled = true`；
- `moraleSparkleEnabled = true`；
- 旧 `safety.battleWarningMode` 原样保留。

迁移后保存新键。旧键暂不删除，以便旧版本回退；新键存在时始终优先使用新值。

「画面与声音」中的旧「加强受损呼吸提示」入口移除。旧控制器字段可以在完成全部调用迁移后删除；若删除会造成无关的大范围改动，则允许保留一版仅供迁移读取，但不得继续影响运行时效果。

## 数据流与组件边界

1. 设置存储负责默认值、字符串枚举解析和旧键迁移。
2. 设置控制器对外提供原始配置，以及结合总开关后的有效策略。
3. 应用组合层把同一策略传给未卜先知、详细战斗面板、编队简报、舰队中心和陆基卡片。
4. 统一损伤等级函数负责 HP 分类。
5. 视觉策略负责范围和等级过滤；组件只负责渲染。
6. 战斗控制器使用震动策略过滤状态转换。
7. `ShipMoraleMark` 单独接收是否允许星光，不影响其余疲劳元素。

该边界避免设置页面、战斗解析器和各个舰娘卡片分别复制相同判断。

## 测试矩阵

### 纯逻辑测试

- HP 0、25%、刚高于25%、50%、刚高于50%、75%、刚高于75% 的等级边界；
- 闪烁五档分别对健全、小破、中破、大破、HP 0 的真值表；
- 震动四档分别对新进入中破、新进入大破、同等级继续掉血、回血、跨级受损的真值表；
- 总开关关闭时所有非安全状态效果无效，重新开启后子项选择不丢失；
- 显示范围三档对预测侧和编队侧的真值表；
- 同阶段多舰不同损伤等级时的过滤与最严重等级选择。

### 持久化与迁移测试

- 五个新字段默认值和往返持久化；
- 未知枚举值安全回退；
- 旧震动开／关迁移；
- 旧普通／强化呼吸均迁移为全部闪烁；
- 已有新键时不重复迁移或被旧键覆盖；
- 大破进击保护旧值不变。

### Widget 测试

- 战斗设置页面只显示新的统一卡片，画面设置页面不再显示旧入口；
- 总开关关闭时四个子设置不可操作且视觉弱化，重开恢复；
- 所有下拉选项和显示范围可选择并保存；
- 窄屏时设置行不溢出；
- 关闭士气星光后星光消失，但疲劳脸、Cond 标签和出击疲劳警告仍存在；
- `predictionOnly` 下未卜先知敌我双方按等级闪烁，编队不闪烁；
- `fleetOnly` 下编队和陆基按等级闪烁，未卜先知不闪烁；
- `all` 下两侧均按等级闪烁。

### 战斗集成测试

- 中破／大破模式分别调用正确原生震动等级；
- 演习、退避、预测不可信及 HP 未下降仍不震动；
- 受损震动关闭不影响大破进击安全弹窗，但会关闭弹窗伴随的震动；
- 大破进击保护关闭不改变普通受损震动设置。

## 验收标准

- Demo 中确认的五项设置在正式 UI 中保持相同层级、顺序和适配；
- 每个设置组合都按本规格的严格等级和范围生效；
- 任何动态效果关闭后，静态 HP／疲劳信息仍正确；
- 升级用户不会意外丢失大破安全设置；
- 自动化测试覆盖设置、迁移、视觉策略、震动状态转换和关键组合；
- Flutter 分析、相关 Dart 测试及 Android 震动单元测试全部通过。
