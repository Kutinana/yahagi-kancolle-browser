# 未持有装备适配抽屉设计

## 背景

当前装备适配抽屉只能从「持有装备」表格打开。「未持有装备」页面已经展示来自游戏主数据的装备，但卡片不能查看哪些舰娘可以装备。

本次调整让未持有装备复用现有装备适配抽屉，不新增数据库，不修改普通槽或增设装备栏的判定规则。

## 已选方案

采用页面级共用抽屉：持有装备表格与未持有装备卡片都只提交装备主数据 ID，由 `OwnedInventoryPage` 在统一的 `Stack` 中渲染同一个 `EquipmentCompatibilityDrawer`。

没有采用以下方案：

- 在未持有装备视图内复制一套抽屉。该方案会产生两套布局和状态逻辑。
- 为未持有装备单独建立适配数据库。现有主数据与规则已经足够，新增数据源没有必要。

## 交互

- 点击任意未持有装备卡片，从右侧打开现有装备适配抽屉。
- 抽屉的标题、图标、舰娘列表、舰种筛选、搜索、普通槽和增设栏筛选与持有装备完全一致。
- 抽屉中的「持有」表示当前持有且能装备该装备的舰娘；「全部」表示所有能装备该装备的舰娘形态。装备本身是否持有不影响这两个范围。
- 再次点击另一张未持有装备卡片时，抽屉直接替换为新装备。
- 点击关闭按钮、返回键或 `Esc` 时，沿用现有关闭行为。
- 切换到舰娘页面，或切换「持有 / 未持有」范围时关闭抽屉，避免跨列表保留选择。

## 数据流

未持有装备卡片中的 `UnownedEquipmentRow.master` 已经是完整的 `MasterSlotItem`。点击卡片时，把 `row.master.id` 写入页面级 `_selectedEquipmentMasterId`。

页面从 `GameState.masterSlotItems` 解析对应装备主数据，并交给现有 `EquipmentCompatibilityDrawer`。抽屉继续通过 `EquipmentCompatibilityProjection` 和 `EquipmentCompatibilityService` 读取舰娘主数据、装备类型许可、白名单、增设装备栏规则及最低改修要求。

整个链路不读取玩家的装备实例来判断「该装备能否被舰娘装备」，因此适用于未持有装备。

## 状态边界

- 选中装备的主数据被移除时关闭抽屉。
- 在「持有装备」范围内，选中装备的最后一个实例消失时关闭抽屉。
- 在「未持有装备」范围内，选中装备变为已持有时关闭抽屉，因为它已经从当前列表消失。
- 游戏主数据或适配规则更新，但选中装备仍属于当前范围时，保持抽屉打开并刷新内容。
- 规则数据尚未准备好时，继续显示现有等待提示。

## 组件调整

- `OwnedInventoryPage`：把装备抽屉提升为持有与未持有装备视图共用的页面级覆盖层，并根据当前范围判断选中项是否仍有效。
- `UnownedInventoryView`：为未持有装备模式接受选中 ID 与点击回调。
- `_UnownedEquipmentView`：把点击回调传给每张卡片。
- `_UnownedEquipmentCard`：增加可点击材质、选中视觉和可访问性语义。
- `EquipmentCompatibilityDrawer`：不修改视觉和业务逻辑。

## 测试要求

Widget 测试至少覆盖：

- 点击未持有装备卡片打开同一个装备适配抽屉；
- 抽屉显示被点击的未持有装备名称；
- 未持有装备也能在「持有 / 全部」范围中显示正确的可装备舰娘；
- 点击另一张卡片会替换抽屉内容；
- 点击关闭按钮后抽屉消失；
- 切换持有范围或舰娘页面时抽屉关闭；
- 未持有装备在抽屉打开期间变为已持有时抽屉自动关闭；
- 持有装备的原有打开、替换、关闭和实时刷新行为不回归。

实现完成后运行相关 Widget 测试、变更文件静态分析和 `git diff --check`。按用户要求不构建 Debug APK，也不操作用户的热重载会话。
