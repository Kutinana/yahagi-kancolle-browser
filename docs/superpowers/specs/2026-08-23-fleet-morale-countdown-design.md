# 舰队疲劳恢复倒计时设计

## 背景

捞船和连续出击时，用户需要知道舰队还要等待多久才能自然恢复疲劳。当前首页「编队简报」和舰队中心只显示最低疲劳值；系统通知模块已经能估算各舰队恢复至 Cond 49 的时间，但该计时状态封装在通知协调器内部，并受通知开关控制。

本功能让舰队界面与系统通知共享同一份疲劳恢复计时状态。用户可以点击原有「最低疲劳」指标，在最低疲劳值和恢复倒计时之间切换。

## 目标

- 首页「编队简报」和舰队中心详情页均支持点击切换显示模式。
- 两个界面使用同一个全局显示偏好，并在应用重启后保持。
- 每支舰队拥有独立且可持久化的疲劳恢复目标时间。
- 页面倒计时与系统通知使用同一份计时结果。
- 关闭系统通知不影响页面倒计时。
- 保持现有 Cond 自然恢复规则：每 3 分钟恢复 3 点，最高按 49 计算。

## 非目标

- 不修改游戏服务器返回的 Cond 数据。
- 不预测 Cond 49 以上的刷闪恢复。
- 不改变野崎刷闪计时器的现有展示与通知行为。
- 不为每个舰队保存不同的显示偏好。
- 不自动切换显示模式。

## 交互设计

### 显示模式

指标支持两种全局模式：

| 模式 | 标签 | 值示例 |
| --- | --- | --- |
| 最低疲劳 | 最低疲劳 | `32` |
| 恢复倒计时 | 恢复倒计时 | `08:42` |

用户点击指标格后切换模式。首页和舰队中心立即同步；切换舰队时继续沿用当前模式，并显示所选舰队的数据。

首次安装或没有已保存偏好时，默认显示「最低疲劳」。

### 倒计时状态

| 状态 | 显示值 |
| --- | --- |
| 最低 Cond 小于 49，且目标时间在未来 | `MM:SS`；超过 59 分钟时使用 `H:MM:SS` |
| 最低 Cond 大于等于 49 | 已恢复 |
| 目标时间刚刚到达，但服务器尚未刷新 Cond | 已恢复 |
| 舰队为空或舰船数据不完整 | `—` |

倒计时归零后不得显示负数。页面只改变展示，不擅自修改本地 Cond；下一次服务器数据到达后按真实 Cond 重新协调状态。

指标格保留现有尺寸、颜色和排版。可点击区域覆盖整个指标格，并提供能表达当前模式和切换动作的无障碍语义。

## 计时规则

对每支非空舰队计算最低 Cond。仅当最低 Cond 小于 49 时创建自然恢复计时锚点：

```text
neededTicks = ceil((49 - minimumCondition) / 3)
targetAt = observedAt + neededTicks * 3 分钟
```

`observedAt` 使用捕获到当前 Cond 的游戏状态更新时间。计时锚点至少包含：

- 舰队 ID；
- 舰队签名（舰队 ID 与舰船 ID 顺序）；
- 观察时的最低 Cond；
- 观察时间；
- 恢复至 49 的目标时间。

出现以下情况时保留原目标时间：

- 舰队签名未变化；
- 服务器返回的最低 Cond 未变化；
- 最低 Cond 仍小于 49。

出现以下情况时丢弃或重建锚点：

- 舰队编成或舰船顺序变化；
- 服务器返回的最低 Cond 变化；
- 最低 Cond 已达到 49；
- 舰队变为空；
- 舰船数据不完整，无法可靠计算最低 Cond。

应用重启后，仅当持久化锚点的舰队签名和当前舰队一致时恢复该锚点。

## 架构设计

### 共享疲劳恢复控制器

从 `GameNotificationCoordinator` 中抽出自然疲劳恢复计时职责，建立独立的共享控制器。该控制器：

- 监听 `GameStateController`；
- 维护各舰队的自然恢复锚点；
- 通过现有锚点存储实现持久化；
- 提供按舰队查询目标时间和当前状态的只读接口；
- 在状态变化时通知舰队 UI 和通知协调器。

共享控制器属于游戏状态能力，不受通知总开关、疲劳通知开关或常驻通知开关影响。

### 通知模块

`GameNotificationCoordinator` 不再私自创建或清理自然疲劳锚点。它从共享控制器读取目标时间，用于：

- 疲劳恢复预提醒；
- 疲劳恢复完成提醒；
- 常驻通知中的剩余时间和进度。

通知设置只决定是否发布通知，不决定计时状态是否存在。

### 舰队界面

首页 `FleetSummaryCard` 和舰队中心的指标栏接收：

- 当前显示模式；
- 切换显示模式的回调；
- 共享疲劳恢复控制器。

两个界面继续复用 `SecondTickBuilder` 的统一秒级时钟。共享控制器只在游戏状态变化时通知，不自行创建每秒定时器。

### 显示偏好

显示模式加入现有布局设置体系。`LayoutSettingsController` 负责读取、切换、通知和保存；`LayoutSettingsStore` 使用独立的 SharedPreferences 键持久化。

该偏好是全局值，不跟随舰队 ID。默认值为最低疲劳模式。

## 本地化

新增或复用以下文案，并同步简体中文、繁体中文和日文资源：

- 恢复倒计时；
- 已恢复；
- 最低疲劳与恢复倒计时之间的切换语义。

时间值使用半角数字和冒号，不随语言变化。

## 错误与降级处理

- 锚点存储读取失败：使用空锚点启动，页面仍显示最低疲劳或 `—`。
- 锚点保存失败：保留当前会话中的内存状态，并沿用项目现有错误上报方式。
- 舰船数据缺失：不推测恢复时间，显示 `—`。
- 设备时间变化：每次渲染根据绝对目标时间重新计算剩余时长；恢复应用前台时立即刷新。
- 通知权限被拒绝或通知服务关闭：页面倒计时继续工作。

## 测试策略

### 计时控制器

- 最低 Cond 40 时生成 9 分钟目标时间。
- 同一舰队和相同最低 Cond 的无关状态刷新不推迟目标时间。
- 最低 Cond 或舰队签名变化时重建锚点。
- Cond 达到 49、舰队为空或数据不完整时清除锚点。
- 合法锚点可跨应用重启恢复；签名不匹配的锚点被丢弃。
- 通知关闭时仍维护锚点。

### 显示偏好

- 默认显示最低疲劳模式。
- 点击切换后立即通知监听者并持久化。
- 重新加载控制器后恢复上次模式。

### 舰队界面

- 首页和舰队中心均可点击切换。
- 任一界面切换后，另一界面读取同一模式。
- 多舰队切换显示各自的最低 Cond 或倒计时。
- 倒计时按秒递减，归零显示「已恢复」，不会显示负数。
- 空舰队和数据不完整时显示 `—`。
- 现有最低疲劳模式和其他舰队指标布局不回归。

### 通知回归

- 预提醒、完成提醒和常驻通知继续使用相同目标时间。
- 关闭通知后页面计时保留；重新启用通知后不重置目标时间。
- 野崎刷闪通知与计时逻辑不受影响。

## 验收标准

- 用户可以在两个舰队界面点击「最低疲劳／恢复倒计时」指标切换模式。
- 两个界面同步显示同一模式，且重启应用后保持。
- 同一舰队的页面倒计时与系统通知目标时间一致。
- 连续出击导致最低 Cond 改变后，倒计时按新状态重建。
- 切换舰队时显示对应舰队的独立倒计时。
- 关闭系统通知后，页面倒计时仍可正常显示和递减。
- 所有新增测试、相关既有测试、静态分析和全量测试通过。
