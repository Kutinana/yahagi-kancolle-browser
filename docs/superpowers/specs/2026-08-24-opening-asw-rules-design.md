# 先制反潜 TAG 规则补全设计

## 背景

当前 `detectShipCombatMechanisms` 使用简化的先制反潜判定。日向改二被错误地写成舰船 ID `646`，真实舰船 ID `554` 无法进入特殊规则，因此装备 S-51J 时不显示「先反」TAG。现有测试沿用了同一个错误 ID，未能发现问题。

本次以舰娘百科的先制对潜条件表为规则基准，补全母港舰队界面的静态先制反潜能力提示。

## 展示边界

「先反」TAG 表示当前舰娘、面板对潜值和装备组合具备先制反潜能力。

- 不根据当前是否处于昼战动态隐藏。
- 不根据联合舰队第一、第二舰队位置动态隐藏。
- 不因中破、大破或当前舰载机剩余数为 `0` 隐藏。
- 不计算实际战斗中是否存在潜艇目标。

上述条件属于战斗阶段约束，不改变母港中的静态配装能力提示。

## 判定数据

判定继续使用 `MasterShip`、`OwnedShip` 和 `ShipEquipment`：

- 舰船身份使用真实的 `api_mst_ship.api_id`。
- 舰种使用 `shipTypeId`。
- 面板对潜使用 `OwnedShip.antiSub`。
- 装备白板对潜使用 `MasterSlotItem.antiSub`，不额外加入改修值。
- 装备类别使用 `api_type[2]`。
- 声呐同时识别小型声呐图标 `17` 和大型声呐图标 `18`。
- `MasterShip` 新增从 `api_mst_ship.api_maxeq` 解析的各槽原始搭载量。
- 「搭载总和不为 `0`」按舰船主数据中的原始搭载量合计判断，不使用当前 `onSlot` 剩余数，因此舰载机全灭后仍保持正确判定。

## 规则

判定按以下顺序执行，命中任意规则即显示 TAG。

### 无条件发动舰

至少包含规则表明确列出的五十铃改二、龙田改二、杰维斯改、雅努斯改、Samuel B.Roberts 改、Johnston、Fletcher 和夕张改二丁，并保留现有代码中已经收录且经真实舰船 ID 校验的后续改装形态。无条件舰不要求面板对潜或装备。

### 海防舰

Norge（挪威）和 Eidsvold（埃兹沃尔）不应用通用海防舰规则。其他海防舰满足以下任一条件：

- 面板对潜不低于 `60`，且装备任意声呐。
- 面板对潜不低于 `75`，且所有装备的白板对潜合计不低于 `4`。

### 普通水面舰

驱逐舰、轻巡洋舰、重雷装巡洋舰、练习巡洋舰和补给舰需要面板对潜不低于 `100`，并装备任意声呐。具有专属规则的舰船先执行专属规则。

### 轻空母

铃谷航改二、熊野航改二和大鹰型专属舰不应用普通轻空母规则。其他轻空母满足以下任一条件，且舰船主数据的原始搭载量合计必须大于 `0`：

- 面板对潜不低于 `50`，装备声呐，并装备白板对潜不低于 `7` 的舰攻、对潜哨戒机或旋翼机。
- 面板对潜不低于 `65`，并装备白板对潜不低于 `7` 的上述航空装备。
- 面板对潜不低于 `100`，装备声呐，并装备白板对潜大于 `0` 的舰攻或舰爆。

声呐装备能力的差异由游戏自身的可装备限制保障；判定层仍按实际已装备声呐判断。凤翔改二／战和 Gambier Bay Mk.II 可使用任意声呐，其他轻空母通常只能装备零式水中听音机。凤翔改二无法装备对潜哨戒机，因此不会通过不存在的配装触发该分支。

### 护卫空母专属舰

大鹰改／改二、神鹰改／改二、云鹰改／改二、加贺改二护等表中专属舰，在原始搭载量合计大于 `0` 时，装备白板对潜大于 `0` 的舰攻、舰爆、对潜哨戒机或旋翼机即可发动。该分支不要求面板对潜或声呐。

### 航空战舰及其他特殊舰

- 日向改二：装备至少 `1` 架 S-51J／S-51J改，或至少 `2` 架 KA号／O号系列普通旋翼机。
- 扶桑改二、山城改二：面板对潜不低于 `100`，装备零式水中听音机，并在原始搭载量合计大于 `0` 时装备水上爆击机、旋翼机、爆雷投射机或爆雷中的至少一种。
- 熊野丸／熊野丸改：面板对潜不低于 `100`，装备声呐，并在原始搭载量合计大于 `0` 时装备白板对潜大于 `0` 的舰爆、旋翼机或对潜哨戒机。改造前无法形成游戏不允许的舰爆／旋翼机配装。
- 大和改二重、神州丸改：面板对潜不低于 `100`，装备声呐，并在原始搭载量合计大于 `0` 时装备水上爆击机或旋翼机。

日向改二的 S-51J 系通过装备类别 `26` 识别，普通旋翼机通过装备类别 `25` 识别。

## 代码结构

保留 `_canOpeningAsw` 作为唯一入口，提取无副作用的小型装备谓词和计数函数，例如声呐、零式水中听音机、舰攻／舰爆、水爆、旋翼机、对潜哨戒机。舰船 ID 集合集中定义在同一文件，避免测试与实现再次使用互相吻合的错误注释。

`MasterShip` 增加只读的 `slotCapacities` 字段，`game_state_reducer` 从 `api_maxeq` 解析。该字段仅用于需要原始搭载量的规则，不改变现有制空计算继续使用 `OwnedShip.onSlot` 当前搭载数的行为。

本次不引入外部规则文件，不改 TAG 的展示组件，也不重构其他战斗机制判定。

## 测试

在 `test/combat_mechanism_test.dart` 使用真实舰船 ID、舰种 ID、装备类别和图标构造测试状态，至少覆盖：

- 日向改二装备一架 S-51J 时显示 TAG。
- 日向改二装备两架普通旋翼机时显示 TAG，一架时不显示。
- 普通舰分别使用小型、大型声呐满足 `100` 对潜门槛。
- 海防舰 `60 + 声呐`、`75 + 装备白板对潜 4`，以及挪威、埃兹沃尔例外。
- 普通轻空母 `50`、`65`、`100` 三档条件和排除舰。
- 舰载机当前 `onSlot` 为 `0`，但主数据原始搭载量大于 `0` 时仍满足航空装备规则；原始搭载量合计为 `0` 时不满足。
- 护卫空母专属舰的航空装备条件。
- 扶桑／山城、熊野丸、大和改二重、神州丸改的正反例。
- 无条件发动舰不带装备仍显示 TAG。
- `game_state_reducer` 正确保存 `api_maxeq`，并在 `copyWith` 中保留该字段。
