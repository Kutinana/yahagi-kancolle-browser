# 后台通知可靠性修复设计

## 背景

现有通知功能已经能够为远征、入渠、建造、泊地修理和疲劳恢复创建常驻进度与普通完成通知，但在任务状态更新、应用进程恢复和通知投递失败时仍存在竞态。修复目标是在不支持手机重启恢复的前提下，保证应用前台、后台、进程被清理以及重新打开应用后的通知状态一致。

## 目标

- 提前提醒、正常完成和高速完成使用同一个任务通知身份。
- 完成通知一旦到期，不因游戏状态先刷新而丢失。
- 完成通知再次发声或振动，并覆盖对应的提前提醒。
- 常驻任务完成后保持 100% 和“已完成”，直到游戏确认任务已处理。
- 明石、野崎和普通疲劳恢复拥有可恢复、不会漂移的计时锚点。
- 原生通知调用失败时自动有限重试，不静默丢失提醒。
- 常驻任务超过布局容量时不再静默隐藏。

## 非目标

- 不恢复手机重启前的通知和计时器。
- 不增加云端推送服务。
- 不创建多张分类常驻通知。
- 不修改游戏计时规则本身。

## 一、稳定通知身份与投递账本

每个任务使用稳定的 `taskId`，每个任务的普通通知使用由 `taskId` 与本轮任务截止时间生成的稳定通知编号。提前提醒、定时完成提醒和高速完成提醒都引用该编号。

原生快照增加最小投递状态：

- 待投递完成提醒；
- 已投递完成提醒；
- 已显示的提前提醒；
- 最近一次投递失败及重试次数。

完成提醒发布成功后才记录为已投递。游戏状态先移除任务时，如果完成时间已经到达而投递账本尚未确认完成，原生层继续保留并投递完成提醒。提前提醒在完成通知发布时被同编号覆盖。

为防止旧任务永久残留，完成提醒设置 24 小时安全保留期；超过期限仍未成功投递时停止重试并记录可诊断错误。

## 二、任务生命周期

任务采用以下状态：

1. `running`：任务进行中，展示实时进度。
2. `preempted`：提前提醒已经投递，常驻状态仍为进行中。
3. `completed`：完成提醒已经到期或高速完成，进度为 100%。
4. `acknowledged`：游戏状态确认任务已处理，可以移除常驻行和原生账本。

各业务的确认条件：

- 远征：舰队不再处于原远征任务。
- 建造：船坞从完成待领取状态变为空闲或开始下一轮建造。
- 入渠：船坞清空。快速修理发生时先生成本地完成墓碑；下一次权威港口或入渠状态确认后移除。
- 疲劳：权威舰船士气数据达到目标，或舰队组成变化导致原任务失效。
- 泊地修理：明石不再满足工作条件、舰队组成变化，或港口结算确认后移除。

## 三、计时锚点

新增独立的通知计时锚点存储，不再使用整个 `GameState.updatedAt` 推导业务计时。

需要保存：

- 明石泊地修理开始时间与任务签名；
- 野崎刷闪开始时间与任务签名；
- 每支舰队普通疲劳恢复的观测时间、观测士气和目标时间。

任务签名由业务关键字段组成，例如舰队编号、舰船编号与目标类型。重新打开应用时，仅当签名仍匹配当前缓存状态时恢复锚点；签名不匹配则等待新的权威游戏状态创建计时。

普通疲劳恢复只在舰船士气或舰队组成发生变化时重算。材料、装备、任务等无关 API 更新不得移动目标时间。

## 四、失败重试

Flutter 到原生的快照应用按顺序执行，防止旧快照晚于新快照落地。失败时采用 1 秒、3 秒、10 秒的有限退避重试；新快照到来时替换尚未执行的旧快照重试。

原生层只在通知发布成功后消费即时提醒。闹钟调度失败的项目保留为待重试状态，并由前台服务或下一次快照同步触发重试。重试耗尽后通过现有错误回调报告，不阻塞其他任务。

## 五、常驻通知容量

Android 自定义通知最多保留 5 行：

- 前 4 行展示具体任务；
- 第 5 行在任务超过 5 条时展示“另有 N 项”，并显示未展示任务中最近的完成时间；
- 排序规则为：已完成优先，其次按目标时间由近到远，最后按稳定任务编号排序。

这样不会增加多张常驻卡片，也不会让后加入的建造、入渠或疲劳任务因为固定业务顺序而永远不可见。

## 六、文案

泊地修理全部完成通知统一为中文：

- 标题：`泊地修理完成 · <舰队名>`
- 正文：`<舰队名> 中符合条件的舰船预计已全部修复。`

汇总行使用：`另有 N 项进行中或已完成任务`。

## 七、兼容与安全

- 保持现有通知渠道 ID，避免重置用户的系统通知设置。
- 保持提前提醒与完成提醒的声音、振动开关语义。
- 保持 `AlarmManager` 无精确闹钟权限时的降级行为。
- `BroadcastReceiver` 和前台服务继续保持不导出。
- 不记录游戏凭据、URL 或其他敏感数据。

## 八、测试方案

Flutter 测试覆盖：

- 状态在截止时间前、高速完成和截止时间后移除三种路径；
- 快速修理完成墓碑及权威状态确认；
- 普通疲劳目标不受无关 `updatedAt` 变化影响；
- 明石、野崎和疲劳锚点保存、恢复与签名失配；
- 快照串行化和有限重试。

Android 单元测试覆盖：

- 到期完成提醒在任务先消失时仍会投递；
- 提前、正常完成和即时完成共享通知编号；
- 成功投递后清理、失败后保留和重试耗尽；
- 超过 5 条时的排序与汇总行；
- 完成提醒能够再次发声或振动。

最后运行通知专项测试、Flutter 全量测试、Android 单元测试、静态检查和 Debug APK 构建。真机专项测试需要连接设备后执行，重点检查三星 One UI 的横幅、文字颜色、振动和清后台行为。
