# 工具箱与舰队导出设计规格

## 背景

用户需要把 Yahagi 当前捕获的母港编成发送到 noro6 与 Jervis，操作方式与 poi 的舰队导出插件一致。舰队导出只是后续工具集合中的一个功能，因此不放入现有舰队详情页，而是新增独立的「工具箱」工作区。

本规格以已确认的本地 Demo 为视觉基线，同时遵循 Yahagi 现有工作区标题、右上分段按钮和深色面板风格。

## 目标

- 新增独立「工具箱」工作区，为后续辅助工具提供稳定入口。
- 第一项工具为「舰队导出」，支持 noro6 与 Jervis。
- 使用 DeckBuilder v4 JSON 作为共同交换格式。
- 点击目标按钮后，通过系统默认浏览器打开网站并自动带入当前编成。
- 提供导出文本刷新、查看和复制能力。
- 默认只输出活动海域基地航空队；取消筛选时按已捕获顺序输出 DeckBuilder 支持的前 3 队。
- 右上工具切换按钮与建造、战果、设置等页面现有分段按钮保持一致。

## 不在本期范围内

- 不在 Yahagi 内嵌 noro6 或 Jervis 网页。
- 不向第三方上传舰娘实例 ID、账号凭据或其他不属于 DeckBuilder 编成格式的数据。
- 不导出整个母港的舰娘与装备库存。
- 不实现第二项实际工具；「其他」页面只显示开发中状态。
- 不导出活动贴条、缎带等当前 `GameState` 未建模信息。

## 方案选择

### 方案 A：放入舰队详情页

入口接近舰队数据，但会让舰队页继续膨胀，也无法承载未来与舰队无关的工具，因此不采用。

### 方案 B：新增独立工具箱工作区

工具箱拥有自己的侧边导航入口和右上工具切换。舰队导出作为首个工具，未来可以继续增加其他工具。该方案边界清晰，符合用户确认的 Demo，确定采用。

### 方案 C：仅提供系统分享或复制入口

实现最少，但用户仍需手动打开网站并粘贴，无法达到与 poi 一致的一键导出体验，因此不采用。

## 页面结构

### 工作区入口

- 在工作区侧边导航新增「工具箱」。
- 使用稳定 ID `tools`，新增页面索引，不改变现有页面索引。
- 默认顺序放在「持有装备」之后、「设置」之前。
- 现有用户保存过自定义顺序时，菜单顺序归一化逻辑应自动补入 `tools`，同时保留已有项目的相对顺序。

### 顶部上下文栏

- 左侧只显示标题「工具箱」，不显示「将当前母港编成发送至外部舰队工具」等副标题。
- 右侧显示两个分段按钮：「舰队导出」和「其他」。
- 分段按钮复用 `ConstructionModeTabs`、`SenkaModeTabs` 与 `SettingsSegmented` 的视觉规则：高度 38 px、外层 3 px 内边距、深色底、描边、20 px 圆角；选中项使用金色背景与浅金文字。
- 首次进入默认选中「舰队导出」。本期不持久化工具子页选择。

### 舰队导出页

宽屏和手机横屏使用两栏布局：

- 左栏：noro6、Jervis 两个导出目标，以及「仅导出活动海域陆航」开关。
- 右栏：DeckBuilder v4 文本、刷新按钮、复制按钮和系统浏览器提示。

窄屏或竖屏改为单栏滚动，导出目标在前，文本区域在后。页面不显示舰队数量、舰娘数量或基地航空队数量统计。

### 其他页

居中显示「其他功能正在开发」，附带简短的后续工具提示。不提供不可用按钮。

## 数据转换

新增独立的纯 Dart 导出器，由 `GameState` 生成 `Map<String, Object?>`，最后统一使用 `jsonEncode` 序列化，禁止手工拼接 JSON 字符串。

### 顶层字段

- `version`：固定为 `4`。
- `hqlv`：取 `GameState.admiralLevel`。
- `f1` 至 `f4`：按 `GameState.fleets` 的舰队 ID 输出。
- `a1` 起：按筛选后的基地航空队顺序连续编号。

### 舰队字段

- 联合舰队时，在 `f1.t` 输出 `CombinedFleetType.apiValue`。
- 舰娘按舰队中的位置输出为 `s1`、`s2` 等。
- `id`：舰娘 Master ID。
- `lv`：舰娘等级。
- `luck`：当前运值。
- `items`：普通槽位按原始槽位位置输出为 `i1`、`i2` 等；未装备槽位不输出。
- 增设槽装备输出为 `ix`。

### 装备字段

- `id`：装备 Master ID。
- `rf`：改修等级，包含 `0`。
- `mas`：熟练度大于 `0` 时输出。

普通槽位必须按舰娘 `slotIds` 的原始索引编号，不能先过滤空槽再重新编号，否则会改变装备所在槽位。

### 基地航空队字段

- 默认只保留 `areaId >= 30` 的活动海域基地航空队。
- 关闭筛选后按 `GameState.landBases` 的已捕获顺序取前 3 队。DeckBuilder v4 只定义 `a1` 至 `a3`，页面需明确提示该上限，禁止输出会被目标工具静默忽略的 `a4` 及以后字段。
- 中队按原始位置输出为 `i1` 至 `i4`，空中队不输出。
- 装备字段与舰娘装备一致。
- `mode` 取基地航空队的 `actionKind`。

## 外部打开与复制

- noro6 基础地址：`https://noro6.github.io/kc-web/`。
- Jervis 兼容入口：`https://fleethub.madonoharu.workers.dev/`。
- 使用 `Uri.replace(queryParameters: {'predeck': json})` 构造地址，确保 JSON 正确编码。
- 使用现有 `url_launcher`，并指定 `LaunchMode.externalApplication`，交给系统默认浏览器处理。
- 点击导出目标时先重新生成 JSON，再打开外部网站，避免发送旧文本。
- 使用 Flutter `Clipboard` 复制文本。
- 打开失败或复制失败时显示可本地化的错误提示，不清空现有文本。

## 状态与错误处理

- `GameState.hasPortData == false` 时，导出按钮不可用，文本区显示等待母港数据的状态。
- 数据已就绪时，首次进入页面自动生成文本。
- `GameState` 更新后不强制改写用户正在查看的文本；用户点击「刷新」或目标网站按钮时生成最新文本。
- 单条舰娘或装备实例引用缺失时跳过该条目，并保持 JSON 合法；转换器通过测试覆盖这种不完整状态。
- 系统浏览器启动失败时保留文本，用户仍可复制后手动导入。

## 组件边界

- `toolbox_page.dart`：管理当前工具子页并呈现对应内容。
- `toolbox_mode_tabs.dart`：实现与现有页面一致的右上分段按钮。
- `fleet_export_page.dart`：舰队导出布局与用户操作。
- `deck_builder_exporter.dart`：纯数据转换，不依赖 Flutter UI。
- `external_fleet_tool_launcher.dart`：构造目标 URI 并调用外部浏览器，接口可注入以便测试。

## 测试策略

### 单元测试

- 空状态与最小可用状态。
- 4 支舰队、联合舰队类型和舰娘顺序。
- 普通装备、空槽、增设槽、改修等级与熟练度。
- 活动陆航默认筛选、关闭筛选及最多三队上限。
- 基地航空队连续编号。
- JSON 往返解析与字段类型。
- noro6、Jervis URI 的 `predeck` 参数可解码回原 JSON。

### Widget 测试

- 工具箱标题和右上分段按钮。
- 「舰队导出／其他」切换。
- 未取得母港数据时禁用导出。
- 刷新与复制反馈。
- 不显示舰队、舰娘、基地航空队数量统计。
- 手机横屏双栏与窄屏单栏不溢出。

### 导航回归

- 新工具箱入口出现且可进入。
- 默认菜单顺序正确。
- 旧的自定义菜单顺序可迁移并补入工具箱。
- 拖动排序和恢复默认顺序继续有效。
- 现有工作区页面索引与路由行为不变。

## 完成标准

- 用户能从独立工具箱页面一键用系统默认浏览器打开 noro6 或 Jervis，并自动导入当前 DeckBuilder v4 编成。
- 用户能刷新和复制同一份导出文本。
- 活动陆航筛选默认开启，开关行为与 poi 旧版插件一致。
- 右上工具切换与项目现有分段按钮一致。
- 「其他」页显示开发中状态。
- 三种语言文案齐全，相关测试和静态分析通过。
