# 装备开发工作台重构设计

## 背景

装备开发首版已经具备正向概率计算、目标装备选择和配方反推能力，但这些功能同时出现在一个页面中，信息层级混杂。当前结果卡片还暴露逐池概率、最低资源和「被替换出货」等计算细节，用户难以快速确认最终结果。

本次重构不改变开发数据和计算规则，只重组页面信息架构与结果投影。页面采用已经确认的「开发工作台」设计，并继续保持 Yahagi 自有的深海蓝与旧金色视觉风格，不复制参考项目 UI。

## 目标

- 将正向计算和配方反推拆成两个清晰的页内模式。
- 让正向结果只展示实际可出的装备和最终概率。
- 使用表格代替出货胶囊，支持直观的概率排序。
- 将秘书舰选择改为与远征检查一致的双栏二级选择器。
- 将原「目标装备」功能完整迁移到「开发公式」模式。
- 保留现有计算精度、目标组合、配方回填和响应式能力。

## 非目标

- 不修改开发池匹配、正负概率叠加、最低资源或失败率算法。
- 不删除数据中的负概率和最低资源字段；这些数据仍参与最终概率和配方计算。
- 不增加游戏内自动开发、网络同步或历史概率统计。
- 不重新打包 Debug APK；开发阶段继续使用测试、静态分析和热重载验证。

## 页面框架

装备开发页最外层标题统一为「开发工作台」。标题位于工作台卡片左上角，右侧放置紧凑的双项切换按钮：

1. 「开发计算器」；
2. 「开发公式」。

切换按钮属于工作台标题栏，不再单独占用标题上方的一行。切换仅替换工作台主体内容，页面路由、数据集和 `EquipmentDevelopmentController` 保持不变。两个模式共享秘书舰、资源和目标装备状态，因此配方回填后切回计算器可以立即看到对应结果。

窄屏下标题和切换按钮允许上下排列，切换按钮占满可用宽度；宽屏下保持标题左对齐、切换按钮右对齐。

## 开发计算器

### 开发条件

计算器顶部显示：

- 秘书舰类型选择器；
- 当前旗舰信息；
- 油、弹、钢、铝 4 项资源输入；
- 当前判定的开发池类型。

资源输入继续限制在 10–300。每个输入框使用项目现有的资源图片作为前置图标：

- 油：`assets/images/material/01.png`；
- 弹：`assets/images/material/02.png`；
- 钢：`assets/images/material/03.png`；
- 铝：`assets/images/material/04.png`。

图标位于输入内容前方，资源名称作为紧凑标签，不再依赖长文本框标题形成视觉识别。

### 秘书舰二级选择器

点击秘书舰类型后打开居中的双栏对话框，交互复用 `ExpeditionMissionPicker` 的结构与视觉语义：

- 左栏显示秘书舰大类，例如炮战系、水雷系、空母系、潜水系和其他；
- 右栏显示当前大类下的具体开发池选项，例如金刚级、内华达级、黎塞留级或其他条件池；
- 左栏切换大类时只刷新右栏，不关闭对话框；
- 点击右栏选项后立即提交选择并关闭对话框；
- 当前大类和当前具体选项都有明确的选中高亮；
- 点击遮罩、关闭按钮或系统返回键取消，不改变当前选择。

左栏大类由可选开发池的稳定分类字段生成，右栏继续使用快照中的本地化池名称。选择结果仍保存开发池稳定键，不使用显示文字作为状态标识。

### 出货概率表

正向结果只保留一个「出货概率」表格。表格只接收最终概率大于 `0` 且满足当前资源门槛的装备，不再显示以下分组：

- 目标出货；
- 其他出货；
- 资源不足；
- 被替换出货。

表格包含以下列：

| 列 | 内容 |
| --- | --- |
| 装备 | 装备图标、名称和可选的「目标」标记 |
| 类型 | 本地化装备类型名称 |
| 最终概率 | 所有兼容池增量相加后的实际概率 |

概率只显示最终结果，例如 `4%`。不再显示 `6% - 2%`、最低资源 `10/20/10/10` 或其他中间计算明细。

当前目标装备永久置顶：

- 单目标时，该装备固定在第一行；
- 多目标时，全部目标装备先于其他装备；
- 目标装备之间和其他装备之间分别遵循当前概率排序方向。

默认按最终概率从高到低排列。点击「最终概率」表头后切换为从低到高，再次点击恢复从高到低。表头使用向下或向上箭头表示当前方向。目标置顶规则不受排序方向影响。

表格在窄屏下允许横向滚动，不通过压缩文字造成截断或布局溢出。

## 开发公式

「开发公式」承接首版的目标装备选择和推荐配方功能，不展示算法说明文章。

### 目标装备

页面顶部提供「选择目标装备」按钮。点击后继续使用现有装备选择底部面板：

- 搜索入口保持圆形按钮加独立搜索弹窗；
- 不恢复常驻长条搜索框；
- 支持装备类型筛选、多目标选择和不可共同开发项置灰；
- 已选择目标以紧凑标签显示在公式页顶部；
- 取消最后一个目标后回到引导空状态。

目标状态与计算器共享。切回计算器时，已选择目标在出货概率表中保持置顶和「目标」标记。

### 可用公式表

选择目标装备后显示「可用公式」表格，布局参考已确认的紧凑数据表，但使用 Yahagi 自有配色。列顺序固定为：

1. 秘书舰；
2. 油；
3. 弹；
4. 钢；
5. 铝；
6. 总资源；
7. 池类型；
8. 出货率；
9. 失败率。

「秘书舰」显示完整的大类与具体池名称，例如「炮战系－金刚级」。「出货率」表示所有已选目标装备的合计最终概率。

数字列与表头右对齐，文本列左对齐。当前应用的配方使用整行背景高亮和左侧强调线，不使用额外胶囊堆叠。

公式表保留现有排序状态与方向切换能力。默认顺序为目标出货率降序、总资源升序、失败率降序的稳定排序。点击可排序表头后以该列为主排序，再次点击同一表头切换方向。

点击公式行后：

1. 回填油、弹、钢、铝；
2. 切换到该行对应的秘书舰池；
3. 标记该行为当前应用项；
4. 保持在开发公式模式，不自动跳页；
5. 用户切换到开发计算器后立即看到回填配方的出货概率。

## 数据与计算投影

开发数据、负概率明细和最低资源继续完整保留。`calculateDevelopmentRates` 仍输出 `totals` 与 `details`，反向配方也继续使用完整数据。

页面投影调整为：

1. 先按现有规则计算每件装备最终概率；
2. 排除最终概率小于或等于 `0` 的装备；
3. 排除不满足当前资源门槛的装备；
4. 将目标装备与其他装备合并为一个列表；
5. 按「目标优先、概率方向、稳定 ID」排序。

资源不足装备的概率仍计入开发失败率。被正负增量完全抵消的装备仍保留在计算结果和回归测试中，但不投影到 UI。

## 组件边界

为避免 `equipment_development_page.dart` 继续膨胀，本次按职责拆分以下 UI 单元：

- `equipment_development_page.dart`：工作台外壳、模式状态和响应式组合；
- `development_secretary_picker.dart`：秘书舰大类分组、双栏对话框和选择结果；
- `development_output_table.dart`：正向结果过滤、目标置顶和概率排序表格；
- `development_recipe_table.dart`：可用公式数据表、排序和行回填交互；
- `development_equipment_picker.dart`：现有目标装备底部面板，继续复用。

纯计算文件不依赖 Widget。UI 排序可以通过控制器状态表达，但最终概率过滤必须使用现有计算结果，不重新实现概率算法。

## 本地化

简体中文、繁体中文和日文增加或调整以下语义：

- 开发工作台；
- 开发计算器；
- 开发公式；
- 选择秘书舰类型；
- 出货概率；
- 最终概率；
- 可用公式；
- 池类型。

不再被 UI 使用的「资源不足」「被替换出货」文案可以保留在生成的本地化接口中，避免无关的生成代码清理扩大本次改动范围。

## 错误与边界

- 数据尚未加载或加载失败时，两个模式共用现有错误状态与重试入口。
- 秘书舰大类没有可选池时不显示空分类；右栏没有选项时禁用确认行为。
- 当前已选池在数据更新后不存在时，回退到控制器默认池。
- 未选择目标时，公式页只显示选择按钮和引导文字。
- 多目标没有共同公式时保留所有选择，并显示现有无结果提示。
- 最终概率表为空时显示局部空状态，不显示空表头。
- 相同概率使用装备 ID 作为稳定次排序，避免重建时行顺序跳动。
- 横屏、窄屏和大字体场景不得出现 RenderFlex 溢出。

## 测试要求

### 纯逻辑测试

- 正负概率仍按原算法得到最终值；
- 最终概率小于或等于 `0` 的装备不进入可见结果；
- 资源不足装备不进入可见结果，但失败率保持原值；
- 单目标和多目标均固定在其他装备之前；
- 默认概率降序，切换后升序，再次切换恢复降序；
- 相同概率按稳定 ID 排列。

### Widget 测试

- 标题显示「开发工作台」，右侧存在两个模式按钮；
- 模式切换只显示对应主体，并保留共享状态；
- 点击秘书舰类型打开双栏选择器；
- 左栏切换大类后右栏内容变化，点击右栏选项后提交并关闭；
- 4 项资源输入前显示正确资源图标；
- 正向页面只显示「出货概率」表格，不显示旧分组和最低资源；
- 目标行固定置顶，点击最终概率表头只重排各自分区；
- 公式页复用目标装备面板，不出现常驻搜索框；
- 选择目标后出现 9 列公式表；
- 点击公式行回填资源和秘书舰池，高亮应用行且不自动切换模式；
- 宽屏、窄屏和大字体布局无溢出。

### 回归验证

- 现有开发数据、池匹配、配方生成和参考向量测试全部通过；
- 运行开发模块 Widget 测试与控制器测试；
- 运行完整 `flutter analyze`；
- 最终运行全量 Flutter 测试，但不执行 Debug APK 打包。

## 验收标准

- 页面标题、右侧模式切换和 V4 Demo 一致。
- 秘书舰类型通过双栏二级菜单完成选择。
- 开发计算器只显示实际可出装备的最终概率表。
- 目标装备永久置顶，概率默认降序并支持升降序切换。
- 开发公式通过目标装备反推出与确认截图结构一致的可用公式表。
- 配方行可以回填开发计算器，并保持两个模式的共享状态。
- 不显示其他出货、资源不足、被替换出货或逐池概率明细。
- 相关测试与静态分析通过，开发过程中不重新打包 Debug APK。
