# 未卜先知节点阵形记忆设计

## 目标

在“未卜先知”卡片的航行到点状态中，显示玩家上一次在同一海域节点选择的我方阵形。行为与 poi 的阵形提示保持一致：记录跨应用重启保留，到点时显示，进入战斗后隐藏。

## 范围

- 保存普通出击与联合舰队战斗中确认过的我方阵形。
- 使用“海域 ID + 地图编号 + 内部节点 ID”区分节点。
- 在未卜先知的紧凑模式和完整模式中显示相同提示。
- 提供默认开启的显示开关。
- 不保存演习阵形，不显示首次到点占位文本，不区分舰队、活动难度或血条。
- 本次不记录烟幕类型、敌方阵形或阵形使用次数。

## 交互设计

提示放在航行状态导航头部右侧，与联合舰队类型、节点类型等标签并列，样式沿用现有胶囊标签。

- 普通舰队示例：`上次：单横阵`
- 联合舰队示例：`上次：第四警戒`
- 无历史记录：不渲染标签。
- 进入战斗、战斗结果或返回母港：不渲染标签。
- 关闭设置项：不渲染标签，但保留既有记录并继续维护记录，以便重新开启后立即可用。

阵形名称复用现有 `formationLabel()` 映射，包括 `1–6` 和 `11–14`。未知或无效值不写入存储，也不显示。

## 数据模型与存储

新增独立的阵形记忆存储边界，避免让 `BattleController` 直接依赖 `SharedPreferences`。

```dart
abstract interface class FormationMemoryStore {
  Future<Map<String, int>> load();
  Future<void> save(Map<String, int> formations);
}
```

生产实现使用 `SharedPreferences` 保存一个 JSON 对象；内存实现用于单元和组件测试。

节点键统一由一个纯函数生成：

```text
<mapAreaId>-<mapInfoNo>-<internalNodeId>
```

示例：`1-1-5`。使用内部节点 ID 而不是显示字母，避免 FCD 地图标签变化影响既有记录。

存储值为我方阵形整数。载入时忽略格式损坏、键非法或阵形值不受支持的条目；整份 JSON 无法解析时返回空记录，不阻断应用启动。

## 组件职责

### FormationMemoryController

- 启动时从 `FormationMemoryStore` 载入全部记录到内存。
- 提供同步的节点查询，保证 `map/start` 和 `map/next` 处理期间无需等待磁盘查询。
- 在战斗结果确认后覆盖当前节点记录并异步持久化完整映射。
- 相同节点写入相同阵形时不重复保存。
- 写入顺序串行化，避免快速事件导致旧快照覆盖新快照。

### BattleController

- 通过构造参数接收已载入的 `FormationMemoryController` 或只读/写入接口。
- 处理地图到点事件时，将该节点的历史阵形放入导航态 `LiveBattle.lastFormation`。
- 处理战斗结果时，从已确认战斗数据的 `friendFormation` 更新当前节点记录。
- 演习、未知节点、未知阵形和未形成有效战斗结果的流程不写入。

### LiveBattle 与界面

- `LiveBattle` 新增可选的 `lastFormation` 字段，并由 `copyWith` 完整保留。
- 紧凑模式和完整模式的导航头部使用同一个阵形记忆标签组件。
- 标签只在 `displayStage == navigation`、设置开启且值有效时渲染。
- 进入战斗后，界面继续使用现有 `friendFormation` 展示本次实际阵形，不再展示历史标签。

### 设置

- 在战斗预测设置中增加“显示上次选择的阵形”开关，默认开启。
- 设置通过现有战斗预测设置存储与控制器持久化。
- 切换即时刷新未卜先知卡片，不清除阵形历史。

## 数据流

```text
应用启动
  → FormationMemoryStore.load()
  → FormationMemoryController 内存缓存

map/start 或 map/next
  → 解析海域与内部节点
  → 查询内存缓存
  → LiveBattle.lastFormation
  → 导航头部显示“上次：…”

战斗阶段
  → LiveBattle 进入 battle 状态
  → 历史标签隐藏

战斗结果
  → 读取已确认的 friendFormation
  → 更新当前节点缓存
  → FormationMemoryStore.save()
```

## POI 对齐说明

poi 的未卜先知插件使用“出击地图 ID + 当前内部节点”查询历史，并将历史保存在本地存储中；在导航态有记录时显示，在战斗结果阶段更新。Yahagi 使用 Flutter 的 `SharedPreferences` 替代浏览器 `localStorage`，但保持同样的用户可见生命周期。

Yahagi 的键显式拆分为海域 ID、地图编号和内部节点 ID，语义等价且便于测试与诊断。

## 错误处理

- 存储读取失败：使用空记录启动，不影响游戏捕获和战斗预测。
- 存储写入失败：保留当前进程内的最新记录；错误只进入诊断信息，不中断战斗事件管线。
- 非法阵形：忽略，不覆盖已有有效记录。
- 缺少地图上下文或演习：不查询、不写入。

## 测试策略

1. 存储测试：空值、合法 JSON、损坏 JSON、非法键值和读写往返。
2. 控制器测试：节点隔离、覆盖更新、重复值不写入、串行写入。
3. 战斗控制器测试：到点读取、首次无记录、结果后更新、演习不记录、非法阵形不覆盖。
4. 组件测试：完整模式和紧凑模式均在导航态显示 A 位置标签；开战后隐藏；联合舰队阵形名称正确；关闭设置后隐藏。
5. 回归测试：现有战斗预测、节点标签和设置持久化测试全部通过。

## 验收标准

- 用户在一个有效出击节点完成战斗后，再次到达同一节点能看到上次阵形。
- 关闭并重启应用后记录仍存在。
- 不同海域、地图或内部节点不会串用记录。
- 提示位置、颜色、间距与确认的 A 方案一致。
- 首次到点和进入战斗后均不显示历史标签。
- 功能关闭时不显示，重新开启后历史记录仍可用。
