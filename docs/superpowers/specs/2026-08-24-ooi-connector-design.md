# Yahagi／OOI 双连接模式设计

日期：2026-08-24  
状态：已实现，待真机分模式验收
目标平台：Android

## 1. 背景

Yahagi 当前固定从 DMM 官方舰队 Collection 入口启动游戏。部分用户希望使用 [OOI](https://ooi.moe/) 完成第三方辅助登录，再进入官方游戏服务器。

OOI 当前提供 3 种入口：模式 1 获取 `api_token` 后进入 `/browser`，模式 3 进入 `/poi`，模式 4 使用直连入口。现有单机实测中模式 1、3 进入后断线，模式 4 可以运行，但这不能代表其他用户环境。因此 Yahagi 只把 OOI 作为可选登录入口，完整保留 OOI 自己的模式选择，不代替用户决定模式。

## 2. 目标

1. 在“设置 → 网络”中增加独立的游戏连接方式：
   - `Yahagi 连接`：保持当前 DMM 官方登录和启动行为。
   - `OOI 连接`：原样打开 OOI 登录页，由用户自行选择模式 1、3 或 4。
2. 保存用户选择，应用重启和 WebView 重建后继续使用选中的连接方式。
3. 切换连接方式后立即生效。游戏已经启动时，先提示切换会中断当前页面。
4. OOI 登录表单由 `ooi.moe` 提供。Yahagi 不读取、不保存、不自动填写账号或密码。
5. OOI 登录成功后，现有 KCSAPI 捕获、舰队、战斗、任务、日志、通知等功能必须与 Yahagi 连接保持一致。
6. OOI 登录或兼容逻辑失效时，Yahagi 连接继续正常工作。

## 3. 非目标

- 不部署、内置或复刻 OOI 服务端。
- 不修改、隐藏或自动选择 OOI 的模式 1、3、4。
- 不承诺 OOI 模式 1、3 能被 Yahagi 的 KCSAPI 捕获和本地缓存完整支持；兼容性由分模式验收结果决定。
- 不读取 OOI 登录表单内容，不存储 DMM 密码，不自动提交登录表单。
- 不放宽到任意第三方域名，不允许通配来源 `*`。
- 不承诺 OOI 长期可用，也不把 OOI 设为默认连接方式。
- 不改变现有系统网络、HTTP 代理和 SOCKS5 代理的含义。

## 4. 方案比较

### 4.1 采用方案：独立连接器设置

在现有网络设置页增加“游戏连接”区域。连接器选择与传输网络设置相互独立：用户可以在任一连接器下继续使用系统网络、HTTP 代理或 SOCKS5 代理。

优点：职责清晰，不破坏现有 `NetworkMode` 数据结构；连接器可以独立持久化、测试和回退。

### 4.2 不采用：把 OOI 加入 `NetworkMode`

`NetworkMode` 描述 WebView 请求使用系统网络、HTTP 代理还是 SOCKS5 代理。OOI 描述登录入口，两者不是同一维度。混用会产生“OOI 是否还能设置代理”等歧义，并增加迁移风险。

### 4.3 不采用：只在登录页增加临时按钮

临时按钮无法保存选择，也不能统一处理游戏中切换、WebView 重建和设置回显。后续兼容逻辑会散落在界面事件中，难以测试。

## 5. 设置与交互

### 5.1 设置结构

“网络”页面从上到下分为两个独立区域：

1. 游戏连接
   - Yahagi 连接
   - OOI 连接（实验性）
2. 网络传输
   - 系统网络／VPN
   - HTTP 代理
   - SOCKS5 代理

首次安装和旧版本升级默认使用 Yahagi 连接。现有 `network_settings_v1` 保持兼容；连接器使用独立的持久化键和独立枚举，例如 `GameConnectorMode.yahagi` 与 `GameConnectorMode.ooi`。

### 5.2 应用切换

用户选择连接方式并点击现有“应用”操作后：

- 目标与当前连接器相同：不重启页面，返回“设置未变化”。
- 尚未进入游戏：保存设置并立即打开目标登录入口。
- 已进入游戏：显示确认对话框。确认后保存并重启游戏页面；取消后不保存，当前页面继续运行。
- 切换到 OOI：无论游戏是否启动，都必须显示第三方登录风险说明。游戏已启动时，将风险说明和中断提示合并为一个对话框。

OOI 风险说明必须明确告知：DMM 账号和密码会提交给 `ooi.moe`，而不是 Yahagi 或 DMM 官方页面；Yahagi 不读取和保存这些字段。

### 5.3 切换结果

- Yahagi 连接入口继续使用现有 `GameLaunchConfig.dmmGameEntry`。
- OOI 连接入口固定为 `https://ooi.moe/`。
- 切换只销毁或重载当前游戏文档，不清除全部 WebView Cookie，不清除本地业务数据库，不修改代理设置。
- 浏览器历史在新连接器启动时重置，避免返回按钮退回旧连接器会话。

## 6. OOI 页面与模式选择

### 6.1 页面行为

Yahagi 对 `https://ooi.moe` 登录页面执行零 DOM 注入：不等待或查询登录表单，不选中任何模式，不隐藏或禁用模式 1、3，不读取登录字段，不点击或提交表单。OOI 页面显示什么，用户就看到什么，并自行承担所选 OOI 模式的可用性差异。

### 6.2 登录后跳转

模式 1 获取 `api_token` 后进入 OOI `/browser`，模式 3 进入 `/poi`，模式 4 经直连入口提供 DMM／OSAPI 官方启动地址。导航策略允许：

- `https://ooi.moe/` 及其同源 HTTPS 路径；
- 现有 DMM、DMM 认证提供方和 `kancolle-server.com` HTTPS 来源。

不允许 `ooi.moe.evil.example`、用户信息 URL、非默认端口或其他 OOI 相似域名。

旧 OOI 实现可能生成 `http://osapi.dmm.com/...`。Yahagi 不全局启用明文流量；只对精确的官方 `osapi.dmm.com` 启动地址尝试升级为 HTTPS，并保留路径与查询参数。若 HTTPS 启动不可用，OOI 连接判定为不兼容并显示错误，不回退到任意 HTTP 白名单。

启动 URL 可能包含敏感令牌。地址栏、日志、诊断导出和错误消息不得显示 query、fragment 或完整原始 URL。

## 7. 架构与职责

### 7.1 连接器配置

新增独立组件负责：

- 定义 `GameConnectorMode`。
- 读取和保存当前连接器。
- 将连接器映射到登录入口。
- 为设置页面提供当前值和切换结果。

该组件不负责应用代理、不操作 Cookie、不执行页面脚本。

### 7.2 切换协调器

切换协调器负责：

- 判断目标连接器是否变化。
- 查询当前是否处于真实游戏画面。
- 请求 UI 展示相应确认文案。
- 只在用户确认后保存设置。
- 让现有游戏环境按新入口重新启动。
- 合并连续点击，避免并发创建多个 WebView 或重复导航。

取消、失败或陈旧回调不得改变已保存设置。

### 7.3 导航策略

`GameNavigationPolicy` 和安全地址显示逻辑增加精确的 OOI 连接器边界。OOI 只属于“允许导航的登录连接器”，不自动成为游戏数据可信来源。

导航策略应根据当前连接器启用 OOI：Yahagi 连接下不接受页面自行跳往 OOI；OOI 连接下允许 OOI 与既有官方来源之间的预期跳转。

### 7.4 页面适配

OOI 登录页保持普通移动网页布局，不启用 1200×720 固定画布。跳转至官方游戏来源并检测到真实游戏容器后，继续使用现有画布缩放、触摸、帧率、音频和截图逻辑。

OOI 页面不做结构适配；自动化测试锁定“没有 OOI 专用 DOM 注入”，避免后续无意改变用户可选模式。

## 8. KCSAPI 捕获边界

OOI 连接的成功标准不是“看到游戏画面”，而是游戏最终运行在现有官方捕获白名单内，并产生完整的 KCSAPI 事件。

预期数据流：

`OOI 登录页 → OOI /connector → DMM／OSAPI 官方启动页 → kancolle-server.com 游戏框架 → Yahagi 文档起始捕获脚本 → Android 来源校验 → Flutter 状态与业务模块`

模式 4 下不应出现来自 `ooi.moe` 的 `kcsapi_response`。模式 1、3 可能让 API 经过 OOI `/kcsapi` 链路；必须分别测试现有捕获是否可用。当前实现不得为兼容模式 1、3直接扩大捕获白名单；若确需信任 OOI 消息来源，应另行设计来源认证、消息完整性和凭据泄漏防护。

首个有效性门槛为同时捕获并解析：

- `/kcsapi/api_start2/getData`
- `/kcsapi/api_port/port`
- `/kcsapi/api_get_member/require_info`

来源必须为现有 DMM 或 `kancolle-server.com` HTTPS 白名单，且不得包含账号密码、Cookie、完整启动 URL 或 `api_token`。

## 9. 错误与回退

| 场景 | 行为 |
|------|------|
| OOI 首页无法访问或被 Cloudflare 拦截 | 显示 OOI 不可用提示，保留 OOI 设置，提供切回 Yahagi 连接的操作。 |
| OOI 页面缺少某个模式 | 保持页面原样，由 OOI 展示可用模式；Yahagi 不自动改选。 |
| OOI 返回非白名单域名 | 阻止导航，显示安全拦截提示。 |
| OOI 返回明文官方启动地址 | 仅尝试升级精确的 `osapi.dmm.com` 为 HTTPS。 |
| 登录后未出现官方游戏画面 | 显示登录链路失败；不修改现有捕获白名单。 |
| 游戏画面出现但未捕获 KCSAPI | 标记 OOI 功能验证失败；用户仍可切回 Yahagi 连接。 |
| 切换或 WebView 重启失败 | 不提交新连接器设置，恢复原连接器状态。 |
| OOI 后续停止服务 | Yahagi 连接不受影响，OOI 设置继续可被用户关闭。 |

## 10. 自动化测试

### 10.1 配置与迁移

- 旧版本无连接器键时默认 Yahagi 连接。
- 两种枚举值可保存、读取和回退未知值。
- 连接器设置与 `NetworkMode`、代理地址和端口互不覆盖。

### 10.2 设置交互

- 网络页显示独立的游戏连接区域。
- 未进入游戏时切换 Yahagi 连接立即重启到 DMM 入口。
- 切换 OOI 时始终出现第三方凭据风险确认。
- 游戏中切换任一连接器时出现中断确认。
- 取消不保存、不导航；确认后只执行一次保存和重启。
- 连点应用、页面销毁和陈旧异步结果不会重复启动。

### 10.3 导航与安全

- OOI 连接下允许精确的 `https://ooi.moe` 根域和路径。
- Yahagi 连接下阻止意外跳往 OOI。
- 阻止 HTTP OOI、非默认端口、用户信息 URL 和恶意后缀域名。
- 官方 OSAPI HTTP 升级只匹配精确主机。
- 安全地址和诊断内容不泄漏查询参数。

### 10.4 OOI 页面零注入

- OOI 页面完成加载后不执行 OOI 专用 JavaScript。
- 模式 1、3、4 的控件保持 OOI 原始可见性和可用性。
- Yahagi 不读取、修改或提交账号密码字段。
- 兼容 WebView 与原生 Activity WebView 的行为一致。

### 10.5 回归

- 现有 Yahagi／DMM 登录、第三方 DMM 认证和游戏启动测试继续通过。
- 现有系统网络、HTTP 代理、SOCKS5 代理和网络诊断测试继续通过。
- 现有 KCSAPI 来源校验保持严格，不加入 `ooi.moe`。
- 现有页面缩放、截图、音频、帧率、刷新和游戏 iframe 重载测试继续通过。

### 10.6 Yahagi 本地游戏资源缓存兼容性

Yahagi 本地游戏资源缓存与 OOI 连接器必须保持正交。连接器只决定登录入口；本地缓存仍只处理既有白名单内的官方游戏静态资源，不能缓存 OOI 登录页、`/connector` 页面、登录表单或带 Token 的启动 URL。

自动化测试至少覆盖：

- OOI 连接下，`ooi.moe` 的 HTML、JavaScript、CSS、图片和导航请求不进入本地游戏资源缓存。
- OOI 跳转至官方游戏来源后，既有可缓存资源继续按原规则命中、回源和写入。
- KCSAPI、DMM／OOI 登录请求、POST 请求、含敏感查询参数的启动请求继续不可缓存。
- 切换连接器不清空、不迁移、不重复建立本地资源缓存，也不改变缓存开关、容量、过期时间或基线清单。
- 已有旧缓存、空缓存和损坏／过期缓存均不能把 OOI 连接误导到缓存代理模式。
- 本地缓存关闭时，分别记录 OOI 模式 1、3、4 的登录与 KCSAPI 捕获结果。

## 11. 真机功能验收矩阵

真机测试必须使用专用测试账号，不在日志、截图或测试文档中记录账号、密码、Cookie、Token 或完整启动 URL。Yahagi 连接先执行一遍作为对照，OOI 连接随后执行相同动作。

| 能力 | 关键操作／接口 | 通过标准 |
|------|---------------|----------|
| 登录与母港初始化 | `api_start2/getData`、`api_port/port`、`require_info` | 游戏进入母港，舰队、资源和装备状态完成首次同步。 |
| 舰队与装备 | 编成、换装、补给 | 操作后舰队、装备、制空和索敌相关界面同步更新。 |
| 任务 | 打开任务页、停止或完成测试任务 | 任务中心收到接口并更新状态，不出现长期陈旧数据。 |
| 远征 | 开始一项短远征并领取结果 | 远征计时、完成通知和日志记录一致。 |
| 入渠 | 送入渠并在可行时使用高速修复 | 入渠状态、计时和资源变化同步。 |
| 建造与开发 | 执行最低资源开发；条件允许时执行建造／领取 | 资源、装备／舰船结果和日志正确记录。 |
| 改装与强化 | 执行可逆或低成本的换装／近代化相关操作 | 相关舰船状态刷新，未漏掉成员接口。 |
| 出击与战斗 | 完成一场普通出击，覆盖昼战、结算和回港 | 战斗节点、敌舰、伤害、预测、掉落和战斗日志完整更新。 |
| 联合舰队／活动接口 | 条件允许时执行；否则使用已保存脱敏语料做解析回归 | OOI 不改变事件格式，既有解析测试继续通过。 |
| 战果 | 打开相关页面并触发基础数据更新 | 战果计算依赖的提督经验和战斗结果正常更新。 |
| 通知 | 远征、入渠、建造至少各验证一种可用场景 | 前台与后台通知行为和 Yahagi 连接一致。 |
| 工具栏 | 截图、静音、刷新页面、重载游戏 iframe | 分别记录模式 1、3、4 的结果；操作不能意外切换 OOI 模式。 |
| 生命周期 | 锁屏恢复、切后台、旋转、重启应用 | WebView 和捕获恢复；连接器选择保持不变。 |
| 网络组合 | 系统网络必测；具备环境时测试 HTTP／SOCKS5 代理 | 连接器与代理互不冲突，失败信息能定位到具体层。 |
| 本地资源缓存 | 分别测试关闭、开启且为空、开启且已有资源、清空后重建、过期资源回源 | OOI 登录页不被缓存；进入官方游戏后缓存命中与回源正常；KCSAPI 捕获数量和内容与无缓存对照一致。 |
| 双向切换 | Yahagi → OOI → Yahagi | 确认、取消、历史重置和重新登录均符合设计。 |

如果测试账号不具备某些活动、联合舰队或付费条件，不用真实账号强行制造场景。应使用现有脱敏捕获语料验证解析层，同时在验收报告中明确记录未完成的线上场景。

## 12. 发布门槛

OOI 连接必须同时满足以下条件才可进入公开版本：

1. 真机至少完成 OOI 模式 4 登录并进入官方游戏服务器，同时记录模式 1、3 的实际兼容结果。
2. 捕获并成功解析母港初始化的 3 个关键接口。
3. 真机验收矩阵中所有可执行场景与 Yahagi 连接结果一致。
4. 自动化测试、Flutter 静态分析、Android 单元测试和调试 APK 构建通过。
5. 不扩大 KCSAPI 捕获来源到 `ooi.moe`，不读取登录表单，不泄漏启动 Token。
6. 切回 Yahagi 连接后，官方登录和所有既有功能保持正常。
7. 本地游戏资源缓存的关闭、空缓存、已有缓存、清空重建和过期回源场景全部通过，且不会缓存 OOI 登录链路或改变 KCSAPI 捕获结果。

如果只能登录或显示游戏，但 KCSAPI 捕获不完整，功能仍视为未完成，不得以“实验性”名义绕过发布门槛。

## 13. 文档与对外说明

设置页和发布说明统一使用以下含义：

- “Yahagi 连接”：通过现有 DMM 官方入口登录和启动。
- “OOI 连接（实验性）”：原样打开第三方 OOI 页面；用户可自行选择模式 1、3 或 4，各模式的代理、缓存和 Yahagi 功能兼容性以验收结果为准。

不得使用“OOI 加速”“OOI 缓存可用”或“官方支持”等未经验证的表述。
